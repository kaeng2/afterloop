> 1. 이 worktree 루트에 사람이 입력한 `.env`가 있다. 어떤 방법으로도 열거나 내용·일부를 출력하지 않는다.
> 2. **실제 PayPal 호출을 하지 않는다.** `npm run sandbox:*`를 어떤 옵션으로도 실행하지 않는다 (병합 뒤 컨트롤 타워가 `sandbox:check`와 `RUN_SANDBOX=1` AC13을 돌린다). 가짜 클라이언트 단위 테스트만 한다.
> 3. `tests/sandbox/manifest.json`은 컨트롤 타워가 이미 v2.3 구성으로 고쳐 두었다. **한 글자도 바꾸지 않는다.** `tests/sandbox/last-run.md`도 바꾸지 않는다.
> 4. 실제 분쟁에는 어떤 조치도 하지 않는다. 특히 `PP-R-GAH-10197649`(시연 제외)에 대한 POST는 어떤 경로로도 만들지 않는다.

- `orders` 13건: O01~O12 (시드의 샌드박스 주문 12건) + **O13** (`seoyeon`, `FK-SW-NV`, `tracked: false`, `captureId` 있음). O13은 시드(`seed/orders.json`)에 **없다** — 시드는 바꾸지 않는다.
- `disputes` 4건: `D1`(O02), `D2`(**O13**), `D3`(O08), 그리고 `{ "key": "D2-old", "orderKey": "O01", "demoExcluded": true, "note": "…" }`.

## 고칠 것
1. **manifest 형식** (`scripts/sandbox/manifest.ts`): 분쟁 항목에 선택 칸 `demoExcluded: boolean`, `note: string`을 받는다. 읽고 다시 써도 이 칸들이 지워지지 않는다 (지금은 zod가 모르는 칸을 버린다). 주문 항목은 지금 그대로.
2. **시드에 없는 주문(O13)을 지우지 않는다**: manifest를 다시 쓰는 모든 경로(`sandbox:orders`의 기본·`--fresh`, `sandbox:capture`, `sandbox:setup`의 각 단계)에서, 시드 규격(`readSandboxOrderSpecs`)에 없는 manifest 주문은 **그대로 보존**하고 새로 만들거나 바꾸지 않는다. `--status`·`sandbox:check`는 이런 주문도 조회한다 (상품명·구매자 검사는 manifest의 `buyer`·`sku` 기준).
3. **`sandbox:check`** (`check.ts`·`check-steps.ts`): 보고(`CheckReport`)의 `orders`는 manifest 주문 전부(13건), `disputes`는 manifest 분쟁 전부(시연 제외 포함, 항목에 `demoExcluded` 표시). `last-run.md`에는 시연 제외 분쟁도 ID와 함께 "시연 제외"로 적는다. 주문 수·추적 수를 고정 숫자(12, 7, 5)와 비교하는 코드가 있으면 manifest 기준으로 바꾼다 (`ORDERS_PER_BUYER`·`TRACKED_COUNT` 상수가 쓰이는 곳을 확인한다. 주문 **생성** 쪽 상수는 시드 12건 기준 그대로 둔다).
4. **`sandbox:setup -- disputes`**: 분쟁을 manifest에 맞추는 단계가 다시 실행돼도
   - `demoExcluded: true`인 항목은 건드리지 않고, 그 분쟁 ID를 다른 키(D2)로 다시 배정하지 않는다
   - D2는 O13의 캡처에 걸린 분쟁이다 (O01이 아니다). 주문 → 분쟁 키 배정이 고정 표(O02→D1, O01→D2, O08→D3)라면 manifest에 이미 적힌 `orderKey`를 우선하도록 바꾼다
   - 마지막 확인은 "시연 제외를 뺀 D1·D2·D3이 모두 있다"
5. **안전 규칙 — 분쟁이 걸린 주문에는 추적번호를 등록하지 않는다** (SPEC 9-3): `sandbox:setup -- track`(과 추적 등록을 부르는 모든 경로)는 manifest의 분쟁(시연 제외 포함)이 가리키는 주문(`orderKey`)을 **호출 전에** 빼고, 결과 표에 `분쟁 진행 중이라 제외`로 적는다. `tracked: true`인데 아직 등록 안 된 주문이라도 분쟁이 있으면 호출하지 않는다. O13(`tracked: false`)은 당연히 대상이 아니다. 이 판정은 이름 붙인 순수 함수로 두고 단위 테스트한다.
6. `tracked: false`인 주문에는 어떤 경로로도 추적 등록 호출이 나가지 않는다는 기존 동작을 테스트로 고정한다 (없으면 추가).
