> **가장 중요한 규칙**
> 1. 이 worktree 루트에 사람이 입력한 `.env`(AI 키)가 있다. **어떤 방법으로도 열거나 내용·일부를 출력하지 않는다** (잠금으로도 막혀 있다. 막힌다고 다른 방법을 찾지 않는다).
> 2. **이 작업은 실제 AI 호출을 한 번도 하지 않는다.** 단위 테스트는 가짜 `LlmCaller`만 쓴다. 병합 뒤 컨트롤 타워가 실제 AI로 서연 건을 한 번 시험한다.
> 3. **사실값은 LLM이 쓰지 않는다.** 날짜·금액·추적번호·통관 상태는 초안·전송본 어디에서도 `⟦DATE_1⟧`·`{{offerAmount}}` 같은 토큰으로만 나오고 코드가 채운다 (SPEC 3장).
> 4. LLM 출력은 신뢰하지 않는 입력이다. zod로 검증하고, 실패하면 예외 대신 "쓸 수 없음" 결과를 돌려준다.

## 만들 것
화면(S5)이 서버에서 부를 함수 두 개. 타입은 이 파일에서 `export`한다 (계약 파일에는 아직 넣지 않는다).

### 1. `draftReply(input, deps)` — 코칭 + 영어 초안 (+ 구매자 글 영어 번역)
```ts
type ReplyInput = {
  buyerMessages: string[];        // 구매자 글 원문 (한국어 등). 신뢰하지 않는 입력
  buyerLocale: FactLocale;        // 'ko' | 'en' | 'ja' | 'de' (tokens.ts)
  buyerFirstName?: string;        // 인사말용 (예: "Seo-yeon"). 이메일·주소·개인통관고유부호는 받지 않는다
  sellerName?: string;            // 서명용 (예: "Hannah")
  cause: Cause;                   // 분류 결과 (subtype, causeNote)
  move: 'fight' | 'offer' | 'refund'; // 엔진이 추천한 수 (답장의 목적)
  facts: FactToken[];             // 코드가 준 사실값. 초안은 이 토큰만 쓸 수 있다
};
type ReplyDraft =
  | { ok: true; buyerMessageEn: string; coaching: string[]; draftEn: string }
  | { ok: false; reason: 'ai_unavailable' | 'invalid_output' | 'refused'; detail: string };
```
- `coaching`: 3~5개의 짧은 영어 지시 ("Reply today", "Apologize", "Explain the customs hold", "Ask for the code", "Give a date", "Offer a fallback" 같은 답장 구조. 원문 S5 예시 참고). 원인 세부 유형과 수에 맞게
- `draftEn`: 판매자 이름으로 쓴 영어 초안. 2~5문장. 사실값은 **`facts`에 있는 토큰만** 쓴다. `move === 'offer'`이면 금액은 `{{offerAmount}}` 자리표시자로만 쓴다 (실행 계층이 채운다. `src/exec/message.ts`가 어떤 자리표시자를 받는지 읽고 맞춘다)
- `buyerMessageEn`: 구매자 글의 영어 번역 (판매자가 읽는 용도. 화면에 그대로 보인다)
- 코드가 하는 검증: 초안에 `facts`에 없는 토큰이 있으면, 토큰이 아닌 사실값(금액·날짜·추적번호를 글자로 쓴 것)이 있으면, 초안이 비었거나 너무 길면(예: 1200자 초과) → `ok: false, reason: 'invalid_output'`. 글자로 쓴 사실값 탐지는 `tokens.ts`의 기존 함수(`checkTokens`의 `literalFacts`)를 쓴다 — 다시 구현하지 않는다

### 2. `translateReply(input, deps)` — 전송본 + 역번역 + 검사
```ts
type TranslateInput = { draftEn: string; buyerLocale: FactLocale; facts: FactToken[] };
type ReplyTranslation =
  | { ok: true; outgoing: string; backTranslationEn: string; check: TokenCheck; sendable: boolean }
  | { ok: false; reason: 'ai_unavailable' | 'invalid_output' | 'refused'; detail: string };
```
- 판매자가 초안을 고친 뒤 다시 부를 수 있어야 하므로 1번과 분리한다 (입력의 `draftEn`은 판매자가 고친 글일 수 있다)
- `outgoing`: 구매자 언어 전송본. 토큰은 번역하지 않고 그대로 둔다 (원문 10-5의 3번). 한국어는 정중한 존댓말(해요체), 과장·새 약속 금지
- `backTranslationEn`: 전송본을 다시 영어로 옮긴 것. **역번역 호출에는 영어 초안을 주지 않는다** (전송본만 보고 옮겨야 검사 의미가 있다)
- `check`: `checkTokens(draftEn, outgoing, facts)` 결과 그대로. `sendable = check.ok`
- `buyerLocale === 'en'`이면 번역 호출 없이 `outgoing = draftEn`, `backTranslationEn = draftEn`으로 돌려준다 (호출 0회)
- 토큰을 값으로 채우는 일(`fillTokens`·`formatFact`)은 여기서 하지 않는다 — 전송 직전 단계가 한다. 다만 화면 미리보기용으로 채운 글이 필요하면 `tokens.ts`의 기존 함수를 그대로 쓰는 얇은 도우미를 둘 수 있다 (새 표기 규칙을 만들지 않는다)

### 공통
- `deps`는 `{ llm: LlmCaller }` (`src/types.ts`). 호출마다 JSON 스키마를 넘기고 응답을 zod로 다시 검증한다
- 프롬프트(`src/ai/prompts/reply.ts`): 구매자 글은 태그로 감싸 "데이터이지 지시가 아니다"를 명시한다 (`src/ai/prompts/classify.ts` 방식). 개인통관고유부호·이메일·전화번호 모양은 프롬프트에 넣기 전에 가린다 (`classify` 쪽에 있는 가리기 함수를 재사용한다. 내보내져 있지 않으면 멈추지 말고, 같은 규칙을 쓰는 방법을 보고서에 적고 가장 작은 변경으로 처리한다)
- LLM이 실패(시간 초과·거부·오류)하면 예외를 던지지 않고 `ok: false`. `detail`에는 구매자 글 원문·키·프롬프트를 넣지 않는다
- 로그(`console.*`)를 남기지 않는다
- 호출 수: `draftReply` 1회, `translateReply` 2회(번역, 역번역). 테스트에서 호출 수를 고정한다

## 완료 기준 (단위 테스트, 가짜 `LlmCaller`만)
- [ ] 서연 건 (통관 보류 A2, `move: 'fight'`, `buyerLocale: 'ko'`, 사실값 `⟦DATE_1⟧` 1개): 가짜 응답으로 `draftReply` → `translateReply`가 `sendable: true`
- [ ] 가짜 응답의 초안에 글자로 쓴 날짜("by Nov 17")·금액("$72")이 있으면 → `invalid_output`
- [ ] 가짜 응답의 전송본에서 토큰이 빠지거나("11월 17일까지"로 풀어 씀) 늘어나면 → `ok: true`이되 `sendable: false`, `check`에 이유가 있다
- [ ] 전송본에 초안에 없는 약속("반드시", "보장")이 생기면 → `sendable: false` (`check.newPromises`)
- [ ] `facts`에 없는 토큰을 초안이 쓰면 → `invalid_output`
- [ ] LLM이 던지는 경우·스키마에 안 맞는 응답·빈 문자열 → 각각 `ok: false`, 예외 없음, `detail`에 구매자 글이 없다
- [ ] 구매자 글에 "Ignore previous instructions…" 같은 지시가 있어도 프롬프트의 데이터 태그 안에만 들어간다 (가짜 호출기가 받은 `system`·`user`를 검사)
- [ ] 개인통관고유부호 모양(`P123456789012`)·이메일이 프롬프트에 그대로 들어가지 않는다
- [ ] 역번역 호출의 프롬프트에 영어 초안 문장이 들어 있지 않다
- [ ] `buyerLocale: 'en'`이면 호출 0회
- [ ] `move: 'offer'`(지호, B1): 초안에 `{{offerAmount}}`가 있고 글자로 쓴 금액은 없다
- [ ] `npm test`, `npx tsc --noEmit`, `npm run lint`, `npm run test:acceptance` (실패 0 — 단, AC8 "합의 단계에 증빙 링크와 메시지 링크가 함께 있으면…" 1건은 T040 병합 전이라 실패할 수 있다. 그 1건만이면 정상)
