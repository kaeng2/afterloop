## 목표
시드의 샌드박스 주문 12건을 PayPal 샌드박스에 실제로 만들고(승인 링크 수집), 승인 뒤 캡처한다. T001의 `orders`·`capture` 단계를 이 두 스크립트가 대신한다.

## 만들 것
### `scripts/create-sandbox-orders.ts` (`npm run sandbox:orders`)
- 입력: `seed/orders.json`에서 `source: 'sandbox'`인 12건 (구매자, 금액, 상품). 배정은 `tasks/T001.md` "주문 12건 배정" 표 (O01~O12)
- 주문마다 Orders v2 `POST /v2/checkout/orders` (`intent: CAPTURE`, `purchase_units[].items[].name`에 상품명, 금액은 상품 가격, USD). `PayPal-Request-Id`는 주문 키 기준이라 다시 실행해도 중복 생성되지 않는다
- 응답 `links[rel=approve]`(또는 `payer-action`)를 모아 `reports/sandbox-approve-links.md`에 쓴다: `주문번호 | 구매자 | 금액 | approve URL`
- 주문 ID를 `tests/sandbox/manifest.json`의 `orders[]`에 기록한다 (형식은 `tasks/T001.md`)

### `scripts/capture-sandbox-orders.ts` (`npm run sandbox:capture`)
- 브라우저 에이전트가 12건을 승인한 뒤 실행한다
- manifest의 주문마다 상태를 조회해 `APPROVED`면 `POST /v2/checkout/orders/{id}/capture`, 이미 `COMPLETED`면 건너뜀, 아직 승인 전이면 건별로 "not approved yet"을 출력하고 계속한다
- 캡처 ID를 manifest에 기록하고 건별 결과 요약을 출력한다

### 공통
- PayPal 호출은 `createPayPalClient` (`@/paypal/client`, T002)만 쓴다. `fetch`를 직접 쓰지 않는다
- 클라이언트의 `get`/`call` path는 `/`로 시작하는 상대 경로만 받는다. 쿼리 값은 퍼센트 인코딩해서 넘긴다 (공백이나 스킴 표기가 들어가면 거부된다)
- 테스트에서 가짜 `sleep`을 쓸 때는 가짜 시계(`now`)도 함께 앞으로 옮긴다 (안 그러면 분당 30회 제한에서 테스트가 멈춘다)
- `.env`는 스크립트가 직접 읽는다 (`process.loadEnvFile`). **Client Secret·액세스 토큰을 출력·로그·보고서·manifest·approve 링크 파일 어디에도 남기지 않는다**
- `PAYPAL_BASE_URL`이 샌드박스가 아니면 호출하지 않고 종료 코드 1
