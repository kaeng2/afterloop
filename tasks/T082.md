## 수정 가능 폴더
- `src/app/_server/disputes.ts` (realTracking 연결만), `src/app/cases/history.ts`, `tests/unit/` 관련 테스트
- 보내기 관문·데모 모드·기록 규칙 무변경. 엔진·AI·계약·설정·시드·인수 테스트 읽기만

## 만들 것
1. 분쟁이 걸린 주문의 **실제 추적 등록 여부를 읽는다**: 분쟁 → 샌드박스 주문(`tests/sandbox/manifest.json`의 disputes.orderKey → orders.orderId — 이미 `src/paypal/track-orders.ts` 등에서 읽는 방법이 있으면 그것을 쓴다)을 찾아 **주문 상세 GET**(`/v2/checkout/orders/{id}`, `isOrderUntracked`)으로 확인 → `realTracking`으로 넘긴다. 조회는 GET만 (공개 모드에서도 허용). 같은 요청 안에서 한 번만 (캐시). 조회 실패면 "모름".
2. 사건 기록: `hasTrackingInPayPal`이 **확실히 false일 때만** "No tracking in PayPal" 사건을 만든다. 모름(null)이면 만들지 않는다.
3. 엔진 보드(`boardReal.hasTracking`)도 이 실제 값을 쓴다 — 서연·지호는 그대로 false(실제 미등록), Mike는 true. **서연의 "PayPal data only: Full refund $74" 값이 바뀌지 않는지** 테스트로 확인 (O13은 실제 미등록이라 같아야 한다).
