## 목표
모든 PayPal 호출이 지나가는 공통 클라이언트 하나. 토큰 재사용, 재시도, 속도 제한, 요청 ID, 비밀값 비노출을 한 곳에서 강제한다.

## 입력 / 출력 타입 (types.ts 4부, 승인 대기 안)
```ts
export type PayPalEnv = { clientId: string; clientSecret: string; baseUrl: string };
export type ClientDeps = {
  fetch: typeof fetch;
  now: () => number;                    // ms. 테스트에서 시간을 주입
  sleep: (ms: number) => Promise<void>; // 테스트에서 대기를 주입
  log?: (line: string) => void;
};
export type PayPalClient = {
  call: PayPalCaller;                                              // POST (ApiRequest)
  get: (path: string) => Promise<{ status: number; body: unknown }>;
};
export type CreatePayPalClientFn = (env: PayPalEnv, deps: ClientDeps) => PayPalClient;
```
- 공개 함수: `src/paypal/client.ts`의 `export function createPayPalClient` (`CreatePayPalClientFn`)

## 동작
| 상황 | 동작 |
|---|---|
| 첫 호출 | `POST /v1/oauth2/token`으로 토큰 발급 |
| 이후 호출 | 만료 60초 전까지 같은 토큰 재사용 (`deps.now` 기준) |
| 401 | 토큰을 1회 새로 받아 재시도. 또 401이면 에러 |
| 429 | `Retry-After`초(없으면 30초)만큼 `deps.sleep` 후 재시도, 최대 2회. 그래도 429면 에러 |
| 5xx·네트워크 오류 | 2초 → 4초 대기 후 재시도, 최대 2회 |
| 속도 제한 | 최근 60초 동안 30회를 넘으면 `deps.sleep`으로 기다린 뒤 호출 |
| POST | `PayPal-Request-Id: req.requestId`. 재시도할 때 같은 값을 다시 보낸다 |
| `baseUrl`이 `https://api-m.sandbox.paypal.com`이 아님 | 만들 때 에러 (호출 0회) |
| 로그·에러 메시지 | Client Secret, 액세스 토큰, `Authorization` 헤더 값을 넣지 않는다 |

상태 확인용 반복 조회(polling) 루프는 만들지 않는다.
