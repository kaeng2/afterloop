## 목표
모든 PayPal 호출이 지나가는 공통 클라이언트 하나. 토큰 재사용, 재시도, 속도 제한, 요청 ID, 비밀값 비노출을 한 곳에서 강제한다 (SPEC 5-1장).

## 입력 / 출력 타입 (`src/types.ts` 4부)
- `PayPalEnv`, `ClientDeps`(`fetch`, `now`, `sleep`, `log?` 주입), `PayPalClient`(`call`, `get`), `CreatePayPalClientFn`
- 공개 함수: `src/paypal/client.ts`의 `export function createPayPalClient` (`CreatePayPalClientFn`)
- 시간과 대기는 반드시 `deps.now`, `deps.sleep`만 쓴다 (`Date.now`, `setTimeout` 직접 사용 금지). 그래야 테스트가 실제로 기다리지 않는다.

## 동작
| 상황 | 동작 |
|---|---|
| 첫 호출 | `POST /v1/oauth2/token` (Basic 인증, client_credentials)으로 토큰 발급 |
| 이후 호출 | 만료 60초 전까지 같은 토큰 재사용 |
| 401 | 토큰을 1회 새로 받아 재시도. 또 401이면 에러 |
| 429 | `Retry-After`초(없으면 30초)만큼 `deps.sleep` 후 재시도, 최대 2회. 그래도 429면 에러 |
| 5xx·네트워크 오류 | 2초 → 4초 대기 후 재시도, 최대 2회 |
| 속도 제한 | 최근 60초 동안 30회를 넘으면 `deps.sleep`으로 기다린 뒤 호출 |
| POST | `PayPal-Request-Id: req.requestId`, `Content-Type: application/json`. 재시도할 때 같은 값 |
| 응답 | `{ status, body }` (body는 JSON 파싱, 빈 본문은 null) |
| `baseUrl`이 `https://api-m.sandbox.paypal.com`이 아님 | 만들 때 에러 (호출 0회) |
| 로그·에러 메시지 | Client Secret, 액세스 토큰, `Authorization` 헤더 값(Basic 포함)을 넣지 않는다 |

- 상태 확인용 반복 조회(polling) 루프는 만들지 않는다.
- 이 파일은 서버 코드에서만 쓴다. `src/app/`의 `'use client'` 파일에서 import하지 않는다.
