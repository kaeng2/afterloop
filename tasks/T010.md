## 목표
모든 AI 초안(코칭 답장, 색상 문구, 통관 안내, 자동 답변)에서 **사실값은 LLM이 쓰지 않고 토큰으로만** 다닌다 (SPEC v2.1 3장, 원문 10-5). 이 작업은 LLM을 부르지 않는 순수 코드다: 토큰을 뽑고, 초안과 전송본을 비교하고, 검사를 통과한 전송본에 값을 채운다.

## 입력 / 출력 타입
- `FactToken` = `{ token: '⟦DATE_1⟧', kind: 'DATE' | 'AMOUNT' | 'TRACKING' | 'CUSTOMS_STATUS', value: string }`
- 공개 함수 (`src/ai/tokens.ts`)
  - `export const checkTokens: CheckTokensFn` — `(draft, outgoing, facts) => TokenCheck`. `draft`는 판매자가 본 영어 초안(토큰 포함), `outgoing`은 구매자 언어 전송본(토큰 포함, 값 채우기 전)
  - `export function extractTokens(text: string): string[]` — 나온 순서대로, 중복 포함
  - `export function fillTokens(text: string, facts: FactToken[]): string` — 토큰을 `value`로 바꾼다. `facts`에 없는 토큰이 있으면 예외 (채우지 못한 토큰이 구매자에게 가지 않게)
  - `export function formatFact(kind, raw, locale)` — 현지 표기. `DATE`: ISO 날짜(`2026-11-17`) → `ko` "11월 17일", `en` "November 17", `ja` "11月17日", `de` "17. November". `AMOUNT`: 센트 정수 → "$7.20" (모든 언어 공통, USD). `TRACKING`·`CUSTOMS_STATUS`: 그대로

## 동작
1. **토큰 문법**: `⟦` + 대문자 종류 + `_` + 1 이상의 정수 + `⟧` (예: `⟦DATE_1⟧`, `⟦AMOUNT_2⟧`). 종류는 `FactToken['kind']` 네 가지뿐. 이 모양이 아닌 `⟦…⟧`(예: `⟦PCCC⟧`, `⟦date_1⟧`, `⟦DATE_0⟧`)는 토큰이 아니라 **형식 오류**로 보고 `extra`에 원문 그대로 넣는다
2. **`missing`**: 초안에 있는데 전송본에 없는 토큰. 같은 토큰이 초안에 2번, 전송본에 1번이면 1번 부족으로 센다 (개수까지 비교)
3. **`extra`**: 전송본에만 있는 토큰(개수 초과 포함), `facts`에 없는 토큰, 형식 오류
4. **`literalFacts`**: 전송본에 토큰이 아닌 사실값이 직접 적힌 부분. 최소한:
   - `facts`의 `value`가 그대로 적힌 경우, 그리고 `formatFact`로 만든 현지 표기 4개 언어 중 하나가 적힌 경우
   - 금액 모양: `$24`, `$7.20`, `USD 7.20`, `7.20 dollars`, `7달러`, `24ドル`, `24 Dollar`, 전각 숫자·기호
   - 날짜 모양: `11월 17일`, `November 17`·`Nov 17`·`17 November`, `11/17`, `2026-11-17`, `11月17日`, `17. November`
   - 추적번호 모양: 영문 대문자와 숫자가 섞인 10자 이상 열 (예: `1Z999AA10123456784`, `EE123456789KR`)
   - 막지 않을 것: `3 weeks`·`3주`·`2 days` 같은 기간, `1개`·`2 items` 같은 수량, 주문 번호가 아닌 일반 낱말. 경계는 단위 테스트 표로 남긴다
5. **`newPromises`**: 초안에는 없는데 전송본에 생긴 약속 표현. 언어별 목록을 이 파일의 이름 붙인 상수로 둔다 — 영어 `guarantee`, `promise`, `definitely`, `100%`, `without fail` / 한국어 `보장`, `반드시`, `틀림없이`, `무조건`, `약속드` / 일본어 `保証`, `必ず`, `約束` / 독일어 `garantier`, `versprech`, `auf jeden Fall`. 대소문자 무시. 초안에 같은 뜻의 표현이 이미 있으면(예: 초안에 `guarantee`, 전송본에 `보장`) 새 약속이 아니다 — 언어가 달라도 같은 묶음이면 통과시키는 대응표를 둔다
6. **`ok`**: 네 배열이 모두 비어 있을 때만 `true`
7. LLM 호출 없음. `Math.random`, `Date.now` 금지 (`formatFact`의 날짜는 입력 문자열만 쓰고 시간대는 UTC로 고정). 입력을 바꾸지 않는다
8. 개인통관고유부호(`P` + 숫자 12자리)가 전송본·초안에 그대로 있으면 `literalFacts`에 넣되 **값은 가려서**(`P************`) 넣는다 (SPEC 10장: 로그·화면에 남기지 않는다)

## 완료 기준 (단위 테스트)
- [ ] 서연 SC4: 초안 "Your parcel cleared customs on ⟦DATE_1⟧. Tracking: ⟦TRACKING_1⟧." ↔ 한국어 전송본에 두 토큰이 그대로 → `ok: true`. `fillTokens` + `formatFact('DATE', '2026-11-17', 'ko')` → "11월 17일"
- [ ] 전송본에서 토큰 하나가 빠짐 → `missing`, 토큰이 "11월 17일"로 바뀜 → `missing` + `literalFacts`
- [ ] 전송본에 초안에 없던 `⟦AMOUNT_1⟧` → `extra`. `facts`에 없는 토큰 → `extra`. `⟦PCCC⟧` → `extra`
- [ ] 전송본에 "반드시 내일 도착합니다" (초안에는 없음) → `newPromises`. 초안에 `guarantee`가 있고 전송본에 `보장` → 통과
- [ ] 금액·날짜·추적번호 모양 표 (막을 것 / 막지 않을 것) 각 10개 이상
- [ ] `fillTokens`: `facts`에 없는 토큰이면 예외, 채운 결과에 `⟦`·`⟧`가 남지 않음
- [ ] 같은 입력 100회 같은 결과, 입력 불변
- [ ] 인수 테스트 **AC20** (작성 후) 통과
- [ ] `npx tsc --noEmit`에서 자기 파일 오류 없음

## 하지 않을 것
- 번역·역번역·코칭 답장 생성 (LLM 호출. T009·T020·T021에서 이 검사를 쓴다)
- `{{offerAmount}}` 같은 실행 자리표시자 (그건 `src/exec/`가 `plan.amountCents`로 채운다. 여기서는 건드리지 않고 토큰으로도 세지 않는다)
- 실행(`executeMove`)을 거치는 메시지에서 **금액은 `{{offerAmount}}`·`{{refundAmount}}`·`{{disputeAmount}}` 3종만** 쓸 수 있다. `⟦AMOUNT_n⟧`이 남아 있거나 `$72.00`으로 복원된 초안은 실행 층이 거부한다 (T027). 그래서 `fillTokens`는 `{{…}}`를 건드리지 않고 그대로 둔다 (테스트로 확인)
- `formatFact`의 날짜는 `11.17`·`2026.11.17` 같은 점 표기로 만들지 않는다 (실행 층의 금액 검사에 걸린다)
- 원인 분류 (T006), 화면
- 약속 표현 목록을 `config/`로 옮기기 (계약 변경이 필요하다고 보면 보고서에 적는다)
