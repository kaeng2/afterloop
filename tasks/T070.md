> **가장 중요한 규칙**
> 1. **공개 배포의 기본은 `DEMO_MODE=public`이다 (변수가 없거나 모르는 값이어도 public).** public에서는 **실제 PayPal 쓰기 호출이 0회**다 — send-message, make-offer, 환불, 추적(송장) 등록 등 POST/PATCH/PUT/DELETE 전부. 버튼을 누르면 "Simulated" 결과만.
> 2. 실제 전송은 **`DEMO_MODE=recording`일 때만**, 그리고 지금 스위치(`AFTERLOOP_REAL_SEND`, 추적 `AFTERLOOP_TRACK_LIVE`·`AFTERLOOP_TRACK_LIVE_ORDERS`·`AFTERLOOP_TRACK_RECORDING`)와 연결 표 `liveSendAllowed`·판매자 승인 버튼을 **그대로 다 거친 뒤에만**. recording이 아니면 그 스위치들이 켜져 있어도 쓰기 0회.
> 3. 비밀값(Client Secret, AI 키 등)의 **값**을 어디에도 쓰지 않는다 (코드·문서·로그·보고서). `.env`를 열거나 만들지 않는다. 실제 AI·실제 PayPal 호출 금지 — 가짜 호출기로 테스트. 개발 서버를 띄우지 않는다.

## 만들 것

### 1. 모드 (`src/app/_server/mode.ts`)
- `resolveDemoMode(env)` → `'public' | 'recording'`. **정확히 `"recording"`일 때만 recording**, 그 밖(없음·빈 값·`"public"`·오타·대소문자 다름)은 public.
- 서버 전용 (`server-only`). 화면에는 모드 이름만 내려보낸다 (위쪽 막대 또는 전송 모드 글자 옆 작은 "Public demo · simulated sends" — 문구 키. 화면 폴더를 못 고치면 서버가 내려주는 기존 전송 모드 글자에 넣는다).

### 2. PayPal 쓰기 막기 — 한 곳에서
- 앱이 쓰는 PayPal 클라이언트(`src/app/_server/paypal.ts`의 `getPayPalClient`)를 감싸서 **public이면 쓰기 메서드(`call` 등 GET 아닌 모든 요청)가 PayPal로 나가지 않게** 한다 — 네트워크 호출 0회, "Simulated" 결과(지금의 가짜 호출기 결과 꼴)를 돌려준다.
- 보내기(`send.ts`)·추적 등록 서버 액션 경로가 모두 이 클라이언트를 지나는지 확인하고, 지나지 않는 경로가 있으면 같은 관문을 둔다. 지금의 `resolveSendMode`(=`AFTERLOOP_REAL_SEND`)와 추적 게이트는 **recording일 때만** 실제로 볼 수 있게: public이면 그 스위치 값과 무관하게 simulated.
- 읽기(GET: 분쟁 목록·상세·주문·거래 조회)는 public에서도 실제 샌드박스. 연습용 분쟁(HEY)·옛 서연 분쟁(GAH)이 화면·기록 어디에도 안 보이는 것은 지금처럼 (연결 표가 거른다) — 테스트로 다시 확인.

### 3. AI 캐시 (public에서 AI를 거의 부르지 않게)
- `LlmCaller`를 감싸는 캐시 호출기: 키 = `sha256(system + "\u0000" + user + "\u0000" + JSON.stringify(jsonSchema))`. 캐시 파일 `data/ai-cache/llm-cache.json` (`{ version, entries: { [key]: { response, createdAt } } }`)에 있으면 그 응답을 그대로 돌려준다 (실제 호출 0).
  - 프롬프트에는 날짜·금액·이름 **값**이 들어가지 않는다(토큰만) — 그래서 날짜가 바뀌어도 키가 같다. 이것을 테스트로 확인 (같은 분쟁, 다른 `now` → 같은 키).
- 캐시에 없으면: public에서는 **횟수 제한**을 걸고 실제로 부른다 — 프로세스 기준 시간당 최대 N회(`AI_LIVE_LIMIT_PER_HOUR`, 기본 20, 숫자가 아니면 기본값), 넘으면 "AI unavailable" (지금의 `unavailableLlm` 꼴 — 화면은 이미 이것을 처리한다). recording에서는 제한 없음(캐시는 쓴다).
- **캐시 만들기 스크립트** `scripts/ai-cache/build.ts`: 앱과 같은 서버 함수로 서연·지호·Mike 상세의 초안·번역·역번역, 그리고 화면이 부르는 다른 AI 호출(분류·어조·색상 문구가 화면 경로에 있으면 그것도)을 한 번씩 돌리면서, 기록 호출기로 요청 키와 응답을 파일에 쓴다. **이 작업에서는 가짜 LlmCaller로만 시험한다.** 실제 AI로 만드는 것은 컨트롤 타워가 병합 뒤에 `npx tsx --env-file=.env scripts/ai-cache/build.ts`로 한다 — 그 명령과 무엇이 기록되는지를 `reports/deploy.md`에 적는다. 캐시 파일에는 키·응답만 (환경변수·헤더 없음).

### 4. Render
- `render.yaml` (Blueprint): Node 웹 서비스 1개. 빌드 `npm ci && npm run build`, 시작 `npm run start -- -p $PORT` (또는 Next가 `PORT`를 읽는 방식), Node 버전은 `.nvmrc`(22)와 맞춤(`NODE_VERSION` env 또는 `engines`), 상태 확인 경로 `/api/health`, 지역·요금제는 자리만(`plan: free` 등 — 사람이 결제를 정한다, 보고서에 적기). 환경변수는 **이름만** `sync: false`로 (값 없음). `DEMO_MODE`는 `value: public`을 기본으로 둬도 된다.
- `/api/health` 라우트: `{ ok: true, mode: 'public'|'recording', commit?: … }` — 비밀값·env 값 노출 금지 (모드 이름만). PayPal·AI를 부르지 않는다.
- `reports/deploy.md`: 사람이 Render에 넣을 **환경변수 이름 목록**(PayPal 샌드박스 키 이름들, AI 키 이름, `DEMO_MODE`, `AI_LIVE_LIMIT_PER_HOUR`, 녹화 때만 넣는 스위치 이름들과 "공개 배포에는 넣지 않는다"), 각 이름의 뜻 한 줄. **값은 절대 쓰지 않는다.** 배포 순서(Blueprint 연결 → 이름 입력 → 첫 배포 → `/api/health` 확인 → 캐시 데우기), 녹화 날 바꾸는 것(DEMO_MODE=recording + 스위치), 녹화 뒤 되돌리기.
