> **가장 중요한 규칙**
> 1. 영상 흐름(서연 Send → 지호 → 추적)이 막히는 버그다. 원인을 찾아 고친다. 동작·모양·문구는 바꾸지 않는다.
> 2. `_server/send.ts` 관문·`mode.ts`·`activity.ts` 무변경. 실제 AI·PayPal 호출 금지, `.env` 읽기 금지.
> 3. 원인을 확신하지 못하면 고치지 말고 보고서에 근거(파일:줄)와 가설을 적고 멈춘다.

## 재현 (컨트롤 타워가 빌드 + `next start`, `AFTERLOOP_REAL_SEND=0`, Chrome으로 확인한 사실)
1. `/?item=PP-R-GMS-10197661`(서연) → 답장 칸 `Send in Korean` → Simulated 성공 (서버 액션 POST 200, 응답 끝남). 화면에 "What happens next · Simulated"가 뜬다.
2. 왼쪽 목록에서 지호(`/?item=PP-R-MBJ-10197650`)나 추적(`/?item=tracking`) 링크를 누른다 → **주소·화면이 그대로** (28초 기다려도). `window.next.router.push('/?item=…')`도 그대로.
3. Send 하지 않고 같은 링크를 누르면 정상 이동.
4. 관찰:
   - 링크 클릭은 Next `Link`가 정상적으로 `preventDefault` 한다 (가려진 요소 없음, pointer-events auto).
   - headless 녹화에서는 Send 뒤 클릭 때 RSC GET이 **아예 안 나간다**. 다른 브라우저에서는 새 항목 RSC GET이 200으로 끝났는데도 화면이 커밋되지 않았고, 그 뒤 현재 주소(서연) RSC GET이 한 번 더 나갔다.
   - Send 뒤 3초 동안 DOM 변화 0회 (렌더 반복이나 애니메이션 루프가 아님).
   - 즉 라우터 전환(transition)이 시작되지 않거나 끝나지 않는다. 의심할 곳: Send 뒤 켜지는 클라이언트 상태와 컴포넌트 — `cases/progress/case-progress.tsx`(T099 진행 표시), `cases/view/sent-state.tsx`, `today/savings.tsx`(T091·T102 상자), `reply-panel.tsx`의 Send 뒤 경로. 예를 들어 끝나지 않는 Promise로 suspend하는 것, 렌더 중 상태 갱신, 라우터 액션 큐가 비워지지 않는 것.
