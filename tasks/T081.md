> **가장 중요한 규칙 (사람 결정)**
> 1. **화면 글자만 바꾼다**: `config/copy.en.json` ↔ `config/copy.ko.json`, `config/intro.en.json` ↔ `config/intro.ko.json`.
> 2. **바꾸지 않는 것**: 숫자·엔진 결과, **AI가 만든 글**(사건 기록 요약·코칭·칩·초안 — 영어 그대로), 구매자 원문, API 경로 이름, 서버가 읽는 값(데이터·계산·보내기 관문·데모 모드). 계약·인수 테스트는 바꾸지 않는다.
> 3. 기본은 영어. 고른 언어는 쿠키 또는 주소(`?lang=ko`)로 기억한다 (둘 다 되면 주소가 우선). 모르는 값은 영어.
> 4. 실제 AI·PayPal 호출 금지, 개발 서버 금지.

- `config/copy.en.json`·`intro.en.json`은 새 키(언어 버튼 이름 등)를 더할 때만

## 만들 것
1. **버튼**: 위쪽 막대 오른쪽(판매자 칩 옆)에 `EN | 한국어` (시안 v4 모양 — `docs/design/mockup-v4/Desk.dc.html`·`scene1/Scene1.dc.html`의 언어 선택을 참고, 색은 우리 강조색). 고른 쪽 강조, 키보드로 고를 수 있게, `aria-pressed`.
2. **문구 읽기**: `src/app/_shared/copy.ts`의 `t`가 언어를 받게 한다 (`t(key, params, locale = 'en')` 꼴 — 기존 호출은 영어 그대로 동작). 서버 컴포넌트는 요청의 쿠키·주소에서 언어를 읽어 넘기고, 클라이언트 컴포넌트는 내려받은 언어를 쓴다. 파일 머리 주석의 "화면은 영어" 설명을 고친다. 없는 키·남은 자리표시자는 지금처럼 예외 (두 언어 모두).
3. `/intro`의 기존 EN/KO 선택은 같은 쿠키·주소 값을 쓰게 맞춘다 (한 곳에서 고르면 다른 화면도 같은 언어).
4. **ko 문구 점검**: 값이 영어 그대로인 키는 설정 성격 값(시간대·날짜 형식 등)만 남기고 쉬운 한국어로 채운다. 시안 v4에서 새로 생긴 화면의 ko 문구는 **시안의 `ko` 문구(DI.ko)를 우선** 쓴다 (단 시안 ko 중 결정과 어긋나는 것 — 환불 약속·"11/5 약속"·근거 없는 숫자 — 은 쓰지 않는다). 출처 배지 5종 이름은 지금 ko 값 유지.
5. **언어가 바뀌어도 그대로인지** 확인: 금액·%·날짜 숫자(엔진·데이터), AI 글(영어), 구매자 원문, 분쟁 번호.
