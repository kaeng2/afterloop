## 만들 것
1. **PayPal 클라이언트를 프로세스당 하나** (`_server/paypal.ts` `getPayPalClient`): 토큰을 재사용한다. 감싸는 순서는 지금 그대로(클라이언트 → 모드에 따라 `blockWrites` → `recordClient`). 모드·환경값이 다르게 들어오면(시험) 새로 만든다 — 하나로 묶는 열쇠에 비밀값을 넣지 말 것(예: process.env 그대로일 때만 하나를 쓰고 시험에서 env를 넘기면 새로). 속도 제한·재시도 상태가 요청 사이에 공유되는 것을 확인하고 문제 없음을 보고서에.
2. **요청 사이 메모리 캐시 (TTL 90초)**: 분쟁 목록, 분쟁 상세, 주문 조회(GET). 1번과 **반드시 함께**.
   - 쓰기(send-message, make-offer, 추적 등록) **성공 뒤 해당 캐시를 바로 지운다** (녹화 모드에서 보낸 직후 화면이 새 상태를 보여야 한다). 공개 모드의 가짜 성공(`SIMULATED_WRITE`) 뒤에도 지워도 된다(무해).
   - 같은 조회가 동시에 들어오면 한 번만 나가게(진행 중 Promise 공유) — 선택.
   - 캐시가 기록기 서랍("PayPal activity")에 미치는 영향: 캐시에서 꺼낸 것은 실제 호출이 아니므로 새 줄로 남기지 않는다. 서랍 문구가 거짓이 되지 않는지 확인.
3. **병렬**: 분쟁 상세 3건 조회, `buildBoard`·`judgeTone` 반복을 `Promise.all`로. 결과 순서 지금과 같게.
4. **`(app)/layout`의 Today (N)을 `Suspense`로 분리**하고 `src/app/(app)/loading.tsx`를 더한다 — 탭을 누르면 바로 로딩 표시. 로딩 표시는 우리 강조색·문구 파일(`config/copy.*.json` 새 키 — en·ko 둘 다, 키 집합 같게).
5. **Products 처방 토글 재계산을 `startTransition`으로** 감싼다. 숫자는 그대로.
