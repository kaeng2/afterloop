## 할 것 (DECISIONS 20:45 그대로, 다음 시안에도 다시 쓰는 도구)
`scripts/design-diff/`에 Node(playwright-core) 도구:
1. **상태 목록 자동 생성**: 시안 HTML(`<x-dc>` 템플릿 + logic class)의 setState·onClick·타이머를 정적 분석 → 눌러서 갈 수 있는 상태 목록(이름, 클릭 순서) → `states.md`. 사람이 고칠 수 있게 `states.json`(상태 이름 → 시안 쪽 클릭 단계 / 앱 쪽 클릭 단계: 텍스트·역할·selector)로도 낸다. 앱 쪽 단계는 같은 글자·역할로 찾는 것을 기본으로.
2. **재현**: 시안(로컬 정적 서버, `docs/design/mockup-v6` 사본 + vendor react@18.3.1 UMD — `node_modules/react/umd` 등 저장소 안 파일을 쓰거나 실행 인자로 경로 받기)과 앱(URL 인자) 양쪽에서 같은 순서로 상태를 만들고, 1440×1000·1920×1080, `document.fonts.ready` 뒤.
3. **비교** (상태별 폴더 `out/<state>/`):
   (가) 계산된 스타일: 보이는 요소를 글자·역할로 짝지어 color, background, border, border-radius, box-shadow, font-family, font-size, font-weight, line-height, letter-spacing, padding, margin, gap, width, height, x·y, opacity, transform, cursor 비교 → `styles.md`(다른 항목 표)
   (나) 픽셀: **pixelmatch**(devDependency로 추가 허용 — `pixelmatch`, `pngjs`) → `mock.png`·`app.png`·`diff.png`(다른 곳 빨강) + 비율
   (다) 모션: 상태를 바꾸는 동안 `document.getAnimations()`와 transitionstart/end·animationstart 이벤트, setTimeout/setInterval 간격(타이핑 34ms, 단계 1300ms 등 — 페이지에 훅 주입) 기록 → `motion.md`(이름·대상·duration·delay·easing·iterations·간격, 시안과 다른 것 표)
   (라) 녹화: 상태 전환 영상 두 개(webm)
4. **예외 대조**: `exceptions.json`(예외 목록 줄 id → 매칭 규칙: selector/글자/항목)으로 차이마다 "어느 예외 줄 때문인지"를 붙이고, 설명 없는 차이를 따로 센다. 판정 규칙: 설명 없는 차이 0, 픽셀 상태당 ≤0.5%(넘으면 원인 칸).
5. **사람용 한 장** `index.html`: 상태별 [시안 | 앱 | 차이] + 숫자 요약 + 모션 녹화 나란히. 상대 경로라 `reports/design-match/v6/`로 통째 복사해도 열린다.
6. 실행: `npx tsx scripts/design-diff/run.ts --mock <dir> --app <url> --out <dir> [--states s1,s2] [--widths 1440,1920]`. README에 사용법.
- 이 세션은 개발 서버·브라우저 실행 금지 — 단위 시험(정적 분석·짝짓기·예외 대조·md 생성)으로 검증. 실제 실행은 컨트롤 타워.
