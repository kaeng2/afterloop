> **가장 중요한 규칙**
> 1. **화면은 계산하지 않는다.** 기대 손실·점수·판정은 `src/engine/` 결과를 옮기기만 한다.
> 2. **이 화면은 PayPal에 POST를 한 번도 보내지 않는다.** [Run autopilot]은 조회(GET)와 판정만 한다. 분쟁에 대한 자동 실행은 없다 (SPEC 6장).
> 3. PayPal·LLM 호출은 서버 코드에서만 한다. `.env`를 찾거나 만들지 않는다. 실제 호출을 하지 않는다 (가짜 클라이언트로만 시험).
> 4. 연습용 분쟁과 시연 제외 분쟁(`demoExcluded`)은 표·로그·이전 분쟁 수 어디에도 나오지 않는다 (T047의 읽기 함수가 걸러 준다. 이 화면이 따로 읽어 오지 않는다).

## 목표
분쟁과 문의를 한 표에서 위험한 순서로 본다. [Run autopilot]을 누르면 "승인 대기 / 건너뜀"이 규칙 이름과 함께 로그로 나온다. **이 표가 서연 장면의 입구다**: 서연 행이 맨 위에 오고, 누르면 S5로 들어간다. 영상에서 15초, S5 바로 앞. AG Grid 이름을 말하는 순간이 여기다.

## 화면에 보여 줄 것
왼쪽 표 (AG Grid Community), 오른쪽 패널 (오토파일럿).

| 항목 | 무엇을 | 어디서 가져오는지 |
|---|---|---|
| Risk | 점수와 구간 배지 (Low / Watch / High) | `escalationRisk(loaded.signals).score`·`band`. 신호가 없으면 빈칸 |
| Buyer | 이름 | `loaded.buyer.name`. 문의 행은 `SeedInquiry.buyerId` → `seedBuyers` |
| Language | KO / EN / JA / DE | `seedBuyers`의 `language` |
| Type | 세부 유형 칩 (예: B1) + 확신도가 낮으면 "Check type" 배지 | `board.cause.subtype`·`needsReview`. 문의 행은 `SeedInquiry.signal` |
| Amount | 분쟁 금액 | `board.amountCents` → `toDollarsCents` |
| Due | 응답 기한. 없으면 "No deadline" | `board.dueDate` (빈 문자열 = 기한 없음. 날짜를 지어내지 않는다) |
| Suggested | 추천 수와 예상 손실 | `recommend(board).best` → `move`(문구 `move.fight` 등), `expectedLossCents` → `toDollarsRounded` + 'Assumption'. `best`가 없으면 `board.directHandling` 문구 |
| Status | PayPal 상태 | `loaded.statusCode`를 문구 키로 바꿔 표시. D3(Mike)는 PayPal 심사 중으로 보인다 |
| 행 클릭 | 분쟁 행 → `/cases/<disputeId>` | **서연 행을 누르면 S5로 들어간다** |
| 오토파일럿 규칙 3줄 | 고정 문구 | `inbox.rule.*` (원문 8장 S4의 세 문장) |
| [Run autopilot] | 서버에서 분쟁 읽기 → 판정 → 로그 | `loadDemoDisputes()` → 건마다 `recommend` |
| 로그 한 줄 | 시각 · 대상 · 판정 · 규칙 이름 | `recommend(board).autopilot.reason` (엔진이 만든 영어 문장 그대로) + `rule` + `verdict`. 시각은 누른 시각 |
| 안내 한 줄 | "New disputes can take a few minutes to appear in PayPal's list." | 문구 파일 (SPEC 9-4) |

- 행 = 실제 분쟁 (연습용·시연 제외를 뺀 것) + 시드 문의. 종결된 시드 분쟁(D4~D9)은 넣지 않는다.
- **처음 열었을 때 위험 높은 순으로 정렬돼 있다.** 점수가 없는 행은 맨 뒤. 순서는 엔진 점수에서 나온다 (서연을 손으로 맨 위에 고정하지 않는다).
- **로그 3줄은 스크롤 없이 한 화면에 한 번에 보인다.**
- 화면 문구는 하는 일만 말한다. 분쟁에 대해서는 "prepared"·"waiting"·"skipped"만 쓴다 (자동으로 실행한 것처럼 읽히는 문구를 쓰지 않는다).
- 돈이 움직이는 수는 "Waiting for your approval"로만 보인다. 실행 버튼은 이 화면에 두지 않는다.
- AG Grid는 Community 기능만: 정렬, 텍스트 필터, 셀 렌더러, 행 클릭. 행 그룹·set filter·통합 차트·`ag-grid-enterprise`는 쓰지 않는다.

### 배지
- 'Demo data': 시드 문의 행 전체. `loaded.demoFields`에 든 값 — D2의 배송사 정보와 그 결과(A2), D3의 "이전 미수령 2건"과 배송 완료 기록, 서연의 무응답 신호 (SPEC 10장 ①②③).
- 'Assumption': 예상 손실.
- 'AI suggests' / 'Code decides': `cause.source`가 `llm`이면 AI, `rule`이면 Code. 추천·점수·오토파일럿 판정은 항상 Code.
- AI를 못 쓰면 "AI unavailable — showing rules only".

## 보기용 데이터를 만드는 순수 함수 (`src/app/inbox/model.ts`)
DOM·네트워크·시계·난수를 쓰지 않는다. 시각은 인자로 받는다. 인수 테스트(AC19)가 직접 부른다.

- `buildInboxRows(input, params?, rules?)` → 행 배열. `input`: 분쟁마다 `{ board, buyer, statusCode, signals | null, demoFields }`, 문의 배열, 구매자 배열. 안에서 `recommend(board, params, rules)`와 `escalationRisk(signals, rules)`를 **그대로 불러** 결과를 옮긴다. 금액은 `{ cents, display }` 두 개를 함께 둔다.
- `buildAutopilotLog(rows, nowIso)` → 로그 줄 배열 (`reason`·`rule`·`verdict`는 엔진 값 그대로).
- `sortByRisk(rows)` → 정렬된 새 배열.
