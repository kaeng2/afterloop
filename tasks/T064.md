> **가장 중요한 규칙**
> 1. 기록에는 **비밀값·토큰·구매자 개인정보·요청/응답 본문을 넣지 않는다.** 남기는 것: 제목, 메서드, 경로(쿼리 문자열 제외), 응답 코드, 시각, 한 줄 요약(코드가 만든 건수 등), 표시(cached / simulated).
> 2. **연습용 분쟁(HEY, O04)과 시연 제외 분쟁(GAH)은 서랍 어디에도 보이지 않는다** (경로에 그 ID가 들어간 기록은 남기지 않거나 보이지 않게. 목록 조회 요약의 건수도 화면에 보이는 분쟁만 센다).
> 3. **가짜 전송은 실제 호출로 보이지 않는다**: 스위치가 꺼진 상태의 보내기는 "Simulated · not sent" 표시로 남기거나 남기지 않는다 (실제 기록과 섞여 200처럼 보이면 안 된다).
> 4. 실제 AI·실제 PayPal POST 호출 금지 (가짜 호출기로 테스트). 개발 서버를 띄우지 않는다.

## 수정 가능 폴더
- `src/app/_server/paypal.ts`(PayPal 클라이언트를 감싸는 기록기), `src/app/_server/` 안 새 파일(예: `activity.ts`), `src/app/_shared/**`(서랍), `config/copy.*.json`(`activity.` 키)
- `src/app/_server/send.ts`는 **기록기를 통과하게 하는 연결만** (관문 동작은 바꾸지 않는다)
- `tests/unit/` 아래 테스트
- `src/paypal`·`src/exec`·엔진·AI·설정·시드·인수 테스트는 읽기만

## 만들 것
1. **기록기**: 서버에서 앱이 쓰는 PayPal 클라이언트(`getPayPalClient`)를 감싸 호출마다 한 줄을 서버 메모리에 남긴다 (프로세스 메모리, 최근 50개, 최신이 위). 추적 등록·거래 조회·분쟁 조회·send-message·make-offer 모두 같은 클라이언트를 지나야 한다 — 지나지 않는 경로가 있으면 연결하고 보고서에 적는다.
2. **제목·요약 표** (경로 꼴 → 문구 키): 
   - `GET /v1/customer/disputes` → "Read your open cases" · 요약 "N cases" (보이는 분쟁만)
   - `GET /v1/customer/disputes/{id}` → "Read case {짧은 ID}"
   - `POST /v1/customer/disputes/{id}/send-message` → **"Send message"**
   - `POST /v1/customer/disputes/{id}/make-offer` → "Send offer"
   - `POST /v2/checkout/orders/{id}/track` → **"Add tracking"** · 요약 주문 키(O05 등)
   - `GET /v2/checkout/orders/{id}` → "Read order"
   - `GET /v1/reporting/transactions` → **"Read sales"** · 요약 "N transactions" · 캐시에서 준 값이면 **cached** 표시 (캐시 적중도 한 줄로 남기되 "cached"로 구분 — 거래 조회 캐시는 `src/paypal/transactions.ts`. 캐시 적중을 알 수 있는 방법이 없으면 보고)
   - 토큰 발급(`/v1/oauth2/token`)은 남기지 않는다
3. **서랍**: 위쪽 막대 PayPal activity 버튼의 건수 = 기록 수. 서랍 줄: 제목 · 응답 코드 배지(2xx 초록 계열 변수, 그 밖 위험 색) · `METHOD /path` (고정폭 글자) · 시각(판매자 시간대) · 요약 · cached/simulated 표시. 맨 위 설명 "Every call AfterLoop makes on your behalf. Sandbox." 
4. **서연 전송 직후 모습**(영상 끝 2~3초): 녹화 순서대로 쓰면 위에서부터 **Send message 200 · Add tracking 201 (×2) · Read sales 200 cached · Read cases 200** 이 보여야 한다. 보낸 뒤 서랍을 열면 새 줄이 바로 보이게 (서랍을 열 때 서버에서 새로 읽는다).
5. 기록은 서버 재시작 때 사라진다 (그대로 둔다 — 녹화 직전 순서대로 한 번 돈다).
