# T038: `npm run sandbox:disputes` 출력에 `status`·`buyerTexts`·`otherActions` 칸 추가

| 항목 | 값 |
|---|---|
| 기준 SPEC | v2.2 (시작할 때 `SPEC.md` 첫 줄과 비교. 다르면 작업하지 말고 보고) |
| 레인 | paypal |
| 브랜치 / worktree | `lane/paypal` / `../afterloop-wt/paypal` (`.env` 있음) |
| 예상 시간 | 20분 |
| 의존 | **T037 병합 뒤** (`toClassifyInput`이 `evidences`의 구매자 글을 읽는다). 컨트롤 타워가 `main`을 이 브랜치에 병합해 둔다 |

> **가장 중요한 규칙**
> 1. 이 worktree 루트에 사람이 입력한 `.env`가 있다. 어떤 방법으로도 열거나 내용·일부를 출력하지 않는다.
> 2. **실제 PayPal 호출을 하지 않는다.** `npm run sandbox:*`를 실행하지 않는다 (병합 뒤 컨트롤 타워가 한 번 돌린다). 가짜 클라이언트 단위 테스트만 한다.
> 3. `tests/sandbox/manifest.json`, `tests/sandbox/last-run.md`는 바꾸지 않는다.
> 4. 구매자 글 원문은 출력·기록·예외 문구에 싣지 않는다 (개수만).

## 수정 가능 폴더
- `scripts/sandbox/disputes-read.ts`
- `tests/unit/sandbox-disputes-read.test.ts`

## 고칠 것
`disputeReadLines`·`disputesSection`(화면 출력과 `last-run.md` 표)에 칸 3개를 더한다:
- `status` — 분쟁 상세의 `status` (예: `UNDER_REVIEW`). 없으면 `-`
- `buyerTexts=<개수>` — `toClassifyInput`(`@/paypal/mapper`)이 돌려주는 `buyerMessages`의 개수. 변환을 다시 구현하지 않는다. `toClassifyInput`에 넘기는 추적 값은 지금 `toBoardState`에 넘기는 것과 같은 가정(`TRACKING_UNKNOWN`)을 쓰고 `trackingEvents`는 빈 배열
- `otherActions=<rel 목록>` — `links[].rel` 중 `self`와 `MoveType` 4개(`send_message`·`make_offer`·`provide_evidence`·`accept_claim`)가 아닌 것의 이름을 응답 순서대로, 쉼표로. 없으면 `-`
