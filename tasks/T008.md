## 목표
판매자가 승인한 `ActionPlan`을 PayPal 요청으로 바꿔 보낸다. 승인이 없거나 맞지 않으면 **네트워크 호출 전에** 거부하고, 메시지 안 금액과 API 본문 금액이 항상 같게 한다.

## 입력 / 출력 타입
- 입력: `ExecuteInput` (`board`, `plan`, `messageTemplate`, `approval`), `deps: { call: PayPalCaller }`
- 출력: `ExecuteResult`
- 공개 함수: `src/exec/execute.ts`의 `export function executeMove` (`ExecuteMoveFn`)
- 모두 `@/types`에서 가져온다. 새 타입이 필요하면 `src/exec/` 안에만 두고 공개 계약으로 만들지 않는다.

## 동작 (SPEC v2 9-1장)
1. **거부 (호출 0회, `{ ok: false, error, nextAction }`)**
   - `approval`이 null이거나 `approval.planId !== plan.planId`
   - `plan.apiMove`가 `board.allowedMoves`에 없음
   - `accept_claim`인데 `approval.confirmAcceptClaim !== true`
   - 초안에 금액을 직접 쓴 부분 (`$` 뒤 숫자, 숫자 뒤 `USD`·`달러`) 또는 모르는 자리표시자
   - `provide_evidence` (증빙은 multipart 업로드라 이 작업 범위 밖. `nextAction`에 "PayPal 화면에서 직접 증빙 제출"을 안내)
2. **자리표시자 채우기**: `{{offerAmount}}`·`{{refundAmount}}` ← `plan.amountCents`, `{{disputeAmount}}` ← `board.amountCents`. 표기 `$7.20`
   - 센트 → 문자열 변환은 정수 연산으로 한다 (`/100` 후 `toFixed` 같은 부동소수 연산 금지). 새 금액을 계산하지 않는다
3. **요청** (경로는 `/v1/customer/disputes/{disputeId}/...`)

   **한 계획에 호출은 1회다 (SPEC v2 9-1장).**

   | plan.apiMove | 호출 (1회) | 본문 |
   |---|---|---|
   | `make_offer` | make-offer | `{ note: message, offer_amount: { currency_code: 'USD', value: '7.20' }, offer_type: plan.refundType }` |
   | `send_message` | send-message (제안이 없을 때만) | `{ message }` |
   | `accept_claim` | accept-claim | `{ note: message, accept_claim_type: plan.refundType, refund_amount: { currency_code: 'USD', value } }` |

   - 제안할 때는 send-message를 부르지 않는다. 메시지는 make-offer의 `note`에 담는다.
4. **요청 ID**: `requestId = <planId>:<엔드포인트 이름>` (예: `plan-1:make-offer`). 같은 계획을 다시 실행하면 같은 ID가 나간다.
5. **중복 승인**: 같은 `planId`가 이미 성공했으면 다시 호출하지 않고 이전 결과를 돌려준다 (프로세스 메모리 기준. 서버 쪽 중복은 Request-Id가 막는다).
6. **실패**: 2xx가 아니면 `{ ok: false }`. `error`에는 엔드포인트와 상태 코드, `nextAction`에는 사람이 할 일을 적는다.
7. 로그와 결과에 토큰, 구매자 이메일을 넣지 않는다.
