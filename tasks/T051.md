# T051: 단위 테스트를 실제 manifest의 분쟁 수에 묶지 않기 + 연습용 분쟁 확인

| 항목 | 값 |
|---|---|
| 기준 SPEC | v2.5 (시작할 때 `SPEC.md` 첫 줄과 비교. 다르면 작업하지 말고 보고) |
| 레인 | paypal |
| 브랜치 / worktree | `lane/paypal` / `../afterloop-wt/paypal` (`.env` 있음) |
| 예상 시간 | 20분 |
| 의존 | T039 (main에 있음). 컨트롤 타워가 `main`을 이 브랜치에 병합해 두었다 |
| 출처 | 2026-11-10 연습용 분쟁 `P1`을 manifest에 넣자 `npm test` 1건 실패 |

> **가장 중요한 규칙**
> 1. 이 worktree 루트에 사람이 입력한 `.env`가 있다. 어떤 방법으로도 열거나 내용·일부를 출력하지 않는다.
> 2. **실제 PayPal 호출을 하지 않는다.** `npm run sandbox:*`를 실행하지 않는다.
> 3. `tests/sandbox/manifest.json`·`tests/sandbox/last-run.md`·`config/demo-links.json`은 바꾸지 않는다.
> 4. 어떤 분쟁에도 POST 경로를 만들지 않는다.

## 배경
`tests/unit/sandbox-v23.test.ts`의 "정본 manifest는 주문 13건·분쟁 4건이고 시연 제외가 1건이다"가 실제 manifest의 **지금 수**에 묶여 있다. 사람 지시로 연습용 분쟁(`{ key: 'P1', disputeId: 'PP-R-HEY-10197767', orderKey: 'O04', demoExcluded: true }`)이 들어가 분쟁이 5건이 됐고 이 테스트가 실패한다. 연습용 분쟁은 앞으로도 늘 수 있다.

manifest 키 규칙 (AC29와 같다): `D1`~`D3` = 시연 분쟁, `P` + 숫자 = 연습용 분쟁(시연 제외), 그 밖(`D2-old` 등) = 시연 제외.

## 수정 가능 폴더
- `tests/unit/sandbox-*.test.ts`
- `scripts/sandbox/` (아래 2번에서 고칠 것이 있을 때만)

## 고칠 것
1. 실제 manifest를 읽는 단위 테스트는 **수를 고정하지 않는다**. 대신 변하지 않는 것만 본다: 스키마 통과, 다시 직렬화하면 파일과 같다, 시연 제외를 뺀 분쟁 키가 `D1`·`D2`·`D3`, `D2-old`가 시연 제외로 있다, `demoExcluded`가 아닌 분쟁의 키는 `D…`뿐이다, 연습용(`P…`)은 모두 `demoExcluded: true`. 고정된 수가 필요한 검사는 테스트 안에서 만든 가짜 manifest로 한다.
2. 가짜 클라이언트로 확인하고, 안 되면 고친다 (되면 테스트만 추가):
   - `sandbox:check`: 연습용 분쟁도 보고·`last-run`에 "시연 제외"로 나온다 (D2-old와 같은 취급)
   - `sandbox:setup -- disputes` 재실행: `P1`이 보존되고, 그 분쟁 ID가 `D1`~`D3`로 다시 배정되지 않으며, 마지막 확인("시연 제외를 뺀 D1·D2·D3이 모두 있다")이 통과한다
   - `sandbox:setup -- track`: O04(연습용 분쟁의 주문)에 호출 0회
3. 같은 종류의 "지금 수에 묶인" 검사가 다른 `sandbox-*.test.ts`에 있으면 같이 고친다.
