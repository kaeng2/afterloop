## 배경 (실제 AI 시험에서 본 것)
- 프롬프트에 토큰의 이름과 종류만 가서, 모델이 `⟦DATE_1⟧`의 뜻을 실행마다 다르게 골랐다: 한 번은 "그날까지 다시 배송이 진행될 것", 한 번은 "그날까지 배송될 것으로 예상하고 안 오면 **재발송을 준비**".
- 사람 결정: 날짜는 **"판매자가 진행 상황을 확인해서 다시 연락하는 날"** 이다. 도착 예상일이 아니다. 바라는 문장 꼴: "11월 17일까지 운송사 상황을 확인해서 다시 연락드릴게요."
- 사람 결정: AI 초안이 **재발송·환불·할인·무료 배송 같은 돈이 드는 약속을 스스로 만들지 못하게** 한다. 대안은 판매자 정책(설정)에 있는 것만. 정책 밖 약속이 들어가면 전송 가능으로 두지 않고 판매자가 확인하게 한다.

## 수정 가능 폴더

- `src/ai/commitments.ts` (새 파일. 약속 낱말 찾기)

## 만들 것

### 1. 정책 읽기
`config/rules.json`의 `reply`에서 `followUpDateMeaning`과 `allowedCommitments`를 작은 zod 스키마로 읽는 함수 (`ReplyDraftPolicy` 모양. 설정이 틀리면 예외). `draftReply`·`translateReply`는 정책을 선택 인자로 받고, 안 주면 설정을 읽는다 (테스트는 정책을 직접 넘긴다).

### 2. 토큰의 뜻을 프롬프트에 넘긴다
- `<facts>` 줄마다 토큰 · 종류 · **뜻 한 줄**: `⟦DATE_1⟧ (DATE) = the date the seller will check the status and contact the buyer again. Not a delivery date.` 값은 지금처럼 넘기지 않는다
- 뜻의 출처: 답장 후 확인 기한 토큰(`src/engine/followup.ts`의 `FOLLOW_UP_DATE_TOKEN`. import해서 쓴다)은 정책의 `followUpDateMeaning`. 그 밖의 토큰은 `ReplyInput`의 선택 칸 `factMeanings?: Record<string, string>`에 있으면 그것, 없으면 종류별 기본 한 줄 (예: `AMOUNT` = "an amount filled in by code"). 뜻 글자는 한 줄로 접고 태그 글자를 지운다 (T050의 한 줄 값 처리 재사용)
- 시스템 프롬프트에 규칙 추가: 날짜 토큰은 **그 뜻대로만** 쓴다. 뜻이 "다시 연락하는 날"이면 도착·배송·통관 완료 시점으로 쓰지 않는다. 좋은 꼴의 예 한 문장 (예시에 실제 날짜·금액·시연 데이터 값을 넣지 않는다): `I will check with the carrier and contact you again by ⟦DATE_1⟧.`
- 번역 프롬프트에도: 날짜 토큰이 붙은 동사의 뜻을 바꾸지 않는다 ("다시 연락" → "도착"으로 바꾸지 않는다)

### 3. 허용한 약속을 프롬프트에 넘긴다
- `cause.subtype`에 맞는 `allowedCommitments`만 `<allowed_commitments>`에 줄로 넣는다 (없으면 `<none/>`)
- 시스템 프롬프트 규칙: 판매자에게 돈이 드는 약속 — 환불, 재발송, 교환·대체품, 할인·쿠폰, 무료 배송, 보상·적립 — 을 **쓰지 않는다.** 대안이 필요하면 `<allowed_commitments>`에 있는 것만 쓴다. 예외: `move`가 `offer`·`refund`일 때의 환불은 실행 계획이므로 쓸 수 있고 금액은 자리표시자로만 쓴다 (지금 규칙 그대로)
- 코칭 줄에도 같은 규칙 (예: "Offer a refund" 같은 줄을 만들지 않는다. `move`가 `fight`일 때)

### 4. 코드가 정책 밖 약속을 찾는다 (`src/ai/commitments.ts`)
```ts
type CommitmentCategory = 'refund' | 'reship' | 'replacement' | 'discount' | 'free_shipping' | 'compensation';
findCommitments(text: string, locale: FactLocale): CommitmentCategory[]   // 글에서 찾은 범주 (중복 없이, 고정 순서)
```
- 범주별 낱말 목록을 이름 붙인 상수로 한곳에. 영어(초안용)와 한국어·일본어·독일어(전송본용). 예: refund = `refund`, `money back`, `reimburse` / `환불`, `환급` / `返金` / `Rückerstattung`, `erstatten`. reship = `reship`, `re-ship`, `resend`, `send again`, `send a new`, `ship again` / `재발송`, `재배송`, `다시 보내` / `再送`, `再発送` / `erneut senden`, `neu versenden`. replacement = `replacement`, `replace` / `교환`, `대체품` / `交換` / `Ersatz`, `umtauschen`. discount = `discount`, `coupon`, `% off` / `할인`, `쿠폰` / `割引`, `クーポン` / `Rabatt`, `Gutschein`. free_shipping = `free shipping`, `shipping on us` / `무료 배송`, `배송비는 저희가` / `送料無料` / `kostenloser Versand`. compensation = `compensat`, `store credit`, `credit` (낱말 단위) / `보상`, `적립금` / `補償` / `Entschädigung`, `Gutschrift`
- 영어는 대소문자 무시 + 낱말 경계 (`credit card`의 `credit`은 잡지 않는다 — "credit card"·"card company"는 약속이 아니다). 부정문("we cannot offer a refund")도 잡는다 — 막는 쪽이 안전하고 판매자가 확인하면 풀린다
- 자리표시자·토큰 안의 글자는 보지 않는다

### 5. 결과에 정책 밖 약속을 싣는다
- `ReplyDraft`(성공)에 `outsidePolicy: CommitmentCategory[]` 추가 — 영어 초안에서 찾은 범주 중 **허용되지 않은 것**. 허용: `move`가 `offer` 또는 `refund`이면 `refund`. 그 밖의 범주는 지금 정책에 허용 항목이 없으므로 모두 정책 밖이다 (설정의 `allowedCommitments`는 돈이 드는 약속이 아니다 — AC31이 그 글에 이런 낱말이 없음을 지킨다)
- 코칭 줄 중 정책 밖 약속 낱말이 든 줄은 버린다 (T050의 사실값 줄 버리기와 같은 자리. 버린 뒤 3줄 미만이면 `coaching_too_few`)
- `TranslateInput`에 `move`(필수)와 `confirmedCommitments?: CommitmentCategory[]`(판매자가 화면에서 확인한 범주) 추가
- `ReplyTranslation`(성공)에:
  - `outsidePolicy`: 초안(입력 `draftEn`)에서 찾은 정책 밖 범주
  - `addedInTranslation`: 전송본에는 있는데 초안에는 없는 범주 (번역이 약속을 더했다)
  - `sendable = check.ok && addedInTranslation이 비었다 && outsidePolicy의 모든 범주가 confirmedCommitments에 있다`
- 기존 호출부가 깨지지 않게: `move`를 필수로 하면 기존 테스트의 호출을 고쳐야 한다 — 고친다 (기대값이 아니라 입력을 더하는 것이다. 보고서에 적는다)

## 완료 기준 (단위 테스트, 가짜 `LlmCaller`만)
- [ ] 프롬프트: `<facts>` 줄에 뜻이 있고 값은 없다. `FOLLOW_UP_DATE_TOKEN`의 뜻이 정책의 `followUpDateMeaning`과 같다. `<allowed_commitments>`에 A2일 때 두 줄, B1일 때 `<none/>`
- [ ] 가짜 초안 "…I expect delivery by ⟦DATE_1⟧, and if it hasn't arrived I will arrange a reship." → `ok: true`, `outsidePolicy: ['reship']`. 이 초안으로 `translateReply`(가짜 전송본에 "재발송") → `sendable: false`. `confirmedCommitments: ['reship']`를 주면 → `sendable: true`
- [ ] 가짜 초안 "…I will check with the carrier and contact you again by ⟦DATE_1⟧." → `outsidePolicy: []`, 정상 흐름 `sendable: true`
- [ ] 초안에는 약속이 없는데 가짜 전송본에 "전액 환불해 드릴게요"가 생김 → `addedInTranslation: ['refund']`, `sendable: false`, `confirmedCommitments: ['refund']`를 줘도 `false`
- [ ] `move: 'offer'` 초안의 "partial refund of {{offerAmount}}" → `outsidePolicy`에 `refund`가 없다. `move: 'fight'`에서 같은 문장 → 있다
- [ ] `findCommitments`: 범주별 낱말(네 언어) 각각, `credit card`·`card company`·`customs clearance code`·`carrier`는 빈 배열, 부정문은 잡힘, 자리표시자·토큰 안 글자는 무시
- [ ] 코칭 줄 "Offer a refund if it is late"가 `move: 'fight'`에서 버려진다
- [ ] 설정에서 읽은 정책이 스키마를 통과한다. `followUpDateMeaning`이 없거나 `allowedCommitments`가 배열이 아니면 예외
- [ ] T050까지의 테스트: 입력에 `move`를 더하는 것 말고 기대값 변경이 필요하면 **멈추고 보고한다**
- [ ] `npm test`, `npx tsc --noEmit`, `npm run lint`, `npm run test:acceptance` (실패 0)
