## 수정 가능 폴더
- `seed/` (`data.ts`의 종결 손실 값과 주석, `disputes.json`은 `npm run seed`로 다시 생성, `README.md`의 해당 표)
- `tests/unit/seed.test.ts` (기대값)

이 밖은 수정하지 않는다. 특히 `src/`, `config/`, `tests/acceptance/`, `package.json`.

## 목표
종결 분쟁 6건(D4~D9)의 `lossCents`를 분쟁 수수료 f = 1500¢(`config/params.json`의 `feeCents`, SPEC v2.1 5장) 기준으로 바꾼다. 원문 6-4의 값은 "환불액 + 수수료 $8"이었다.

## 규칙 (SPEC v2.1 5장과 같은 기준: 수수료는 질 때만)
| 분쟁 | 원문 결과 | 손실 식 | 이전 | 바뀐 값 |
|---|---|---|---|---|
| D4 | 전액 환불 | 환불액 (수수료 없음) | 5600 | **4800** |
| D5 | 증빙 제출 후 패소 | 환불액 + f | 5600 | **6300** |
| D6 | 대응 지연 패소 | 환불액 + f | 5600 | **6300** |
| D7 | 전액 환불 | 환불액 (수수료 없음) | 4300 | **3500** |
| D8 | 배송 증빙으로 승소 | 0 | 0 | **0** |
| D9 | 셀러 보호 아님 (패소) | 환불액 + f | 19700 | **20400** |
| 합계 | | | 40800 ($408) | **41300 ($413)** |

- 값을 숫자로 직접 적지 말고 **결과 종류(전액 환불 / 패소 / 승소) + 상품 가격 + f**에서 만든다. f는 `config/params.json`의 `params.feeCents.value`를 읽는다 (시드 생성 스크립트가 config를 읽는 것은 허용. 값을 바꾸지는 않는다). f가 바뀌면 `npm run seed`만 다시 돌리면 되게 한다
- 결과 종류는 `SeedDispute` 타입에 필드가 없으므로 `seed/data.ts` 안에서만 쓰고 JSON에는 넣지 않는다 (계약 변경 금지)
- 진행 중 3건(D1~D3)은 `lossCents: null` 그대로. 그 밖의 시드(주문, 문의, 구매자, 상품)는 한 글자도 바뀌지 않아야 한다
