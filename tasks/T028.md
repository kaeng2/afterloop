## 할 일
### 1. 종결 분쟁 손실 재계산 (Q8)
수수료는 SPEC 5장과 같이 **질 때만** 붙인다. 원문 6-4의 값은 "환불액 + 수수료 $8"이었다.

| 분쟁 | 원문 결과 | 손실 식 | 이전 | 바뀐 값 |
|---|---|---|---|---|
| D4 | 전액 환불 | 상품 가격 | 5600 | **4800** |
| D5 | 증빙 제출 후 패소 | 상품 가격 + f | 5600 | **6300** |
| D6 | 대응 지연 패소 | 상품 가격 + f | 5600 | **6300** |
| D7 | 전액 환불 | 상품 가격 | 4300 | **3500** |
| D8 | 배송 증빙으로 승소 | 0 | 0 | **0** |
| D9 | 셀러 보호 아님 (패소) | 상품 가격 + f | 19700 | **20400** |
| 합계 | | | 40800 ($408) | **41300 ($413)** |

- 값을 숫자로 직접 적지 말고 **결과 종류(전액 환불 / 패소 / 승소) + 상품 가격 + f**에서 만든다. f는 `config/params.json`의 `params.feeCents.value`를 읽는다 (읽기만. f가 바뀌면 `npm run seed`만 다시 돌리면 되게)
- 결과 종류는 `SeedDispute` 타입에 필드가 없으므로 `seed/data.ts` 안에서만 쓰고 JSON에는 넣지 않는다
- 대응 시간 비용 t는 더하지 않는다 (원문 식에 없음)

### 2. `SeedDispute.orderId` (Q10)
모든 분쟁이 실제 주문 하나를 가리킨다. 그 주문의 구매자·상품이 분쟁과 같아야 하고, 한 주문에 분쟁은 하나다.

| 분쟁 | 주문 | 비고 |
|---|---|---|
| D1 | O02 | 지호, 가디건 (`tasks/T001.md` 표) |
| D2 | O01 | 서연, 스웨터 |
| D3 | O08 | buyer_m, 비니 세트 (세 번째 미수령 주장) |
| D7 | O09 | buyer_m, 비니 세트 (이전 주장 1, 전액 환불) |
| D8 | O10 | buyer_m, 비니 세트 (이전 주장 2, 배송 증빙으로 승소. 추적 등록 주문) |
| D4·D5·D6·D9 | 그 구매자(B08·B07·B09·B11)의 같은 상품 시드 주문 | D6(미발송 주장)의 주문은 `tracked: false`여야 한다 |

### 3. `SeedOrder.date` (Q10)
모든 주문에 주문일 `date: 'YYYY-MM-DD'`를 넣는다.
- 범위: 시연 시점 2026-11-10 기준 90일 창 **2026-08-12 ~ 2026-11-10** (둘 다 포함)
- **결정적**으로 만든다 (고정 시드 난수 또는 규칙. `Date.now`·`Math.random` 금지. 날짜 계산은 UTC 기준 문자열 연산)
- 이야기와 맞아야 한다: 서연의 O01은 11/9 문의 "벌써 3주째"보다 3주 이상 앞(2026-10-19 이전). buyer_m의 주문 O09 → O10 → O08 순서가 이전 주장 두 건 뒤에 세 번째 주장이 오는 흐름과 어긋나지 않게. 종결 분쟁이 걸린 주문은 창의 앞쪽·중간, 진행 중 분쟁이 걸린 주문은 최근 4주 안. 같은 구매자의 문의(원문 6-3 표의 날짜)가 "배송이 안 온다"는 내용이면 그 주문일이 문의일보다 앞
- 나머지 주문은 창 전체에 고르게 퍼뜨린다 (화면에서 한 날짜에 몰려 보이지 않게)
