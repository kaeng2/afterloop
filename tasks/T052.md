## 배경
실제 PayPal에서 확인한 사실: 판매자가 메시지를 보내면 분쟁이 구매자 답을 기다리는 상태가 되고 `make_offer` 링크가 사라진다. 그래서 추천이 제안인 분쟁(지호)에서는 메시지를 먼저 보내면 안 된다. 화면과 앱 서버 코드가 "이 분쟁은 제안이 먼저인가"를 물을 엔진 함수가 필요하다. 판정은 엔진이 하고 화면은 옮기기만 한다 (SPEC 3장).

## 수정 가능 폴더
- `src/engine/policy.ts`
- `tests/unit/recommend.test.ts` (또는 새 파일 `tests/unit/offer-first.test.ts`)

이 밖은 수정하지 않는다 (`src/types.ts` 계약 그대로. `recommend`·`planMove`의 결과는 바뀌지 않는다).

## 만들 것
```ts
/** SPEC 9-4 "제안이 먼저": 추천이 제안이고 지금 make_offer가 허용돼 있으면 참 — 이때 메시지를 먼저 보내면 안 된다 */
export function offerComesFirst(board: BoardState, recommendation: Recommendation): boolean
```
- 참: `recommendation.best?.move === 'offer'` **그리고** `board.allowedMoves`에 `make_offer`가 있다
- 거짓: 추천이 답장(fight)·환불(refund)·없음(`best = null`)이거나, `make_offer`가 허용돼 있지 않다 (이미 닫혔으면 막을 이유가 없다)
- `recommendation`은 같은 `board`로 만든 것이라고 가정한다. 계산을 다시 하지 않는다 (`recommend`를 안에서 부르지 않는다)
- 순수 함수. 입력을 변형하지 않는다

- [ ] 같은 보드에서 링크에 `make_offer`가 없으면 (구매자 답 대기 상태) → 거짓
