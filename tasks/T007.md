## 수정 가능 폴더
- `seed/` (예: `products.json`, `buyers.json`, `inquiries.json`, `disputes.json`, `orders.json`, `generate.ts`)
- `package.json`: `scripts`에 `"seed"` 한 줄 추가만
- `tests/unit/seed.test.ts`

이 밖은 수정하지 않는다. 특히 `src/`, `config/`, `src/types.ts`, `tests/acceptance/`.

## 목표
모든 화면이 쓰는 데모 데이터를 원문 6장 그대로 만든다. 샌드박스로 실제 만드는 것(주문 12건, 분쟁 3건)은 `source: 'sandbox'`, 나머지는 `source: 'seed'`이고 화면에 'Demo data' 배지가 붙는다.

## 입력 / 출력 타입
`SeedProduct`, `SeedBuyer`, `SeedInquiry`, `SeedDispute`, `SeedOrder` (`@/types` 8부). 파일마다 zod로 검증한다.

## 만들 것
| 파일 | 내용 | 원문 |
|---|---|---|

| `buyers.json` | 12명 B01~B12 (이름, 국가, 언어, 샌드박스 여부, 역할). B01~B05가 샌드박스 | 6-2 |
| `inquiries.json` | 31건: 표의 8건 원문·영어 그대로 + 자동 생성 23건(배송 12, 사이즈 6, 색상 3, 기타 2, 절반 한국어) | 6-3 |
| `disputes.json` | 9건 D1~D9. D1~D3 `source: 'sandbox'`, `status: 'open'`. 종결 손실 D4 4800·D5 6300·D6 6300·D7 3500·D8 0·D9 20400 (센트, 합 41300 = $413. 2026-11-09 Q8 결정으로 f = 1500¢ 기준 재계산, `tasks/T028.md`) | 6-4 |
| `orders.json` | 214건 (90일): 상품별 62·48·33·71. 샌드박스 12건(O01~O12)은 **`tasks/T001.md` "주문 12건 배정" 표와 키·구매자·상품·추적 여부가 행마다 같아야 한다** (그 표가 정본), 나머지 202건 시드. 국가 비율 US 45·KR 25·JP 15·DE 15, 추적 등록 약 60% | 4-1, 6-1, 6-5 |

- **자동 생성은 결정적이어야 한다**: 고정 시드 난수 또는 고정 템플릿. LLM을 쓰지 않는다. 같은 명령이면 같은 파일
- 한국어 자동 문의 문장은 자연스러운 존댓말 템플릿으로 쓴다 (팀이 검수)
- 이름은 모두 가상이다. 이메일·주소·개인통관고유부호 값은 넣지 않는다
- `npm run seed`: 시드 파일을 다시 만들고 zod 검증 후 요약(건수, 합계)을 출력한다. DB 적재는 배포 작업(T025)에서 한다

## 완료 기준
- [ ] 건수: 상품 4, 구매자 12, 문의 31, 분쟁 9, 주문 214 (상품별 62·48·33·71)
- [ ] 종결 분쟁 손실 합계 41300¢ (T028 이후. T007 병합 시점에는 원문 40800¢), 진행 중 3건은 `lossCents: null`
- [ ] 6-2·6-3·6-4 표의 이름·국가·원문 문장이 한 글자도 다르지 않다 (테스트에서 표 값과 비교)
- [ ] 문의 자동 생성 23건의 유형 분포 12·6·3·2, 한국어 비율 50% ± 1건
- [ ] `npm run seed`를 두 번 실행해도 결과 파일이 같다
- [ ] 인수 테스트 **AC17** 통과 (SPEC v2.2 기준으로 작성됨. T028에서 맞춘다)
- [ ] `npx tsc --noEmit`에서 자기 파일 오류 없음

## 하지 않을 것
- 시뮬레이션용 분쟁 확률 (그건 `config/params.json`의 `productRates`, engine 레인)
- 샌드박스 주문 실제 생성 (T001)
- 화면, DB 연결
