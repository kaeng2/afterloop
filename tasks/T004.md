## 동작
1. **검증 (zod)**: 확률 0~1, 금액 0 이상 정수, `offerRate ≤ rules.offer.maxRate`. 어기면 ZodError
2. **p_win**: `board.hasTracking`이면 `params.pWinWithTracking[subtype]`(없으면 `pWin`), 아니면 `params.pWin[subtype]`. 원인이 없으면 계산하지 않고 `best = null`
3. **기대 손실** (SPEC 5장, 센트 정수, 마지막에 사사오입)
   - L_fight = (1 − p_win)(A + f) + t
   - L_offer = p_acc·x·A + (1 − p_acc)(1 − p_win)(A + f) + t
   - L_refund = A + t
4. **분기** (트리 화면용. Σ prob × lossCents = expectedLossCents, 반올림 오차 0.5¢ 이내)
   - fight: `win`(p_win, t) / `lose`(1 − p_win, A + f + t)
   - offer: `accept`(p_acc, xA + t) / `reject_win`((1 − p_acc)·p_win, t) / `reject_lose`((1 − p_acc)(1 − p_win), A + f + t)
   - refund: `refund`(1, A + t)
5. **제안 대상**: `cause.subtype ∈ rules.offer.eligibleSubtypes`(B1, B2)만. 아니면 offer는 `expectedLossCents: null`, `blockedBy: 'OFFER_SCOPE'`, `branches: []`
6. **수 → API** (SPEC 5장 표). API가 `allowedMoves`에 없는 수는 `all`에서 뺀다
7. **추천**: 차단되지 않은 수 중 최소. 동점이면 fight → offer → refund. 없으면 `best = null`
8. **오토파일럿** (SPEC 6장 표, 첫 번째로 걸리는 규칙): F → `skipped/suspected_abuse`, EXTERNAL → `skipped/card_company_case`, 확신도 < 0.7 또는 원인 없음 → `skipped/low_confidence`, `best`가 offer·refund → `awaiting_approval/money_moves`, 그 외 → `awaiting_approval/seller_review`. `reason`은 영어 한 문장 (원문 8장 S4 로그 문체)
9. `Math.random`, `Date`, `performance.now` 금지. 입력 객체를 바꾸지 않는다
