> **가장 중요한 규칙 (안전장치)**
> 1. 고친 영어를 Send하면 **서버에서** 지금 AI 초안과 같은 길로 처리한다: 이름·날짜·금액 값 → 토큰(`⟦BUYER_NAME_1⟧`·`⟦SELLER_NAME_1⟧`·`⟦DATE_1⟧`·…)으로 되돌린 글을 `translateReply`(`src/ai/reply.ts`)에 넘겨 번역 + 역번역 + 검사 → `sendable`이 true일 때만 기존 보내기 경로(`send.ts` 관문 그대로: 공개 모드 Simulated, 녹화 모드만 실제). **AI에 이름 값을 보내지 않는다** (SPEC 3장 v2.9).
> 2. 검사 3개(Facts match·No new promises·Follow-up date)는 **보낼 글 기준으로 다시** 돈다. 실패하면 Send 막고 Details 자동 펼침(T090 그대로). 환불·도착 보장 같은 새 약속은 코드가 막는다(`findCommitments`·`checkTokens`).
> 3. 판매자 화면 미리보기: 번역 중에는 "Translating…" + Send 꺼짐, 끝나면 한국어 전송본과 역번역이 Details에. 번역 실패(AI 없음·한도 초과) → Send 꺼짐 + 이유 한 줄 ("AI unavailable — use the AI draft").
> 4. AI 초안 그대로 보낼 때는 지금처럼 캐시를 쓴다 (바뀌는 것 없음). 공개 모드 AI 시간당 한도·캐시 그대로.
> 5. 실제 AI·PayPal 호출 금지 (가짜로 시험). 개발 서버 금지. `.env` 읽지 않음.

## 만들 것
1. `editGate`를 "고친 글은 보낼 수 없음"에서 "고친 글은 번역·검사를 거쳐야 보낼 수 있음"으로 바꾼다.
2. 이름·날짜 값 → 토큰 되돌리기 함수 (화면에 채워 보이는 값과 짝 — 기존 `fillTokens`의 반대). 되돌릴 수 없는 값이 남으면(예: 판매자가 이름을 다르게 썼다) 그대로 두고 `checkTokens`가 판정.
3. 시험: (a) Add 칩으로 고친 글 → 가짜 LLM 번역 → sendable → 공개 모드 Simulated 보내기, POST 0 (b) "I will refund you in full" 같은 문장을 손으로 넣음 → 검사 실패 → Send 꺼짐 + Details 펼침 (c) 가짜 LLM이 받은 글에 "Seo-yeon"·"서연"·"Hannah" 없음(토큰만) (d) AI 없음 → Send 꺼짐 + 이유 (e) 녹화 모드에서도 관문 그대로.
