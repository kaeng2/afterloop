> **가장 중요한 규칙**
> 1. **화면 상태만**: 이 화면에서 방금 끝낸 항목을 목록 맨 아래 묶음으로 옮긴다. 서버·PayPal을 다시 읽지 않고, 쓰지 않는다. 새로고침하면 원래대로.
> 2. **정직**: 실제로 보내지 않은 것(Simulated)은 끝난 것처럼 말하지 않는다. 분쟁 상태·숫자는 바꾸지 않는다 (목록 항목의 상태 글·위험 값은 그대로 엔진·PayPal 값).
> 3. 실제 AI·PayPal 호출 금지, 개발 서버 금지. `_server/send.ts` 관문·`mode.ts`·`activity.ts` 무변경.

## 시안 동작 (원본: `docs/design/mockup-v4/Desk.dc.html` L632·L682·L706–L716·L40)
- 끝낸 항목(`s.done[id]`)은 원래 묶음(reply/prevent/routine)에서 빠지고, 맨 아래 `done` 묶음에 들어간다. 빈 묶음은 그리지 않는다.
- done 묶음: 제목 `Done today`(ko `오늘 완료`), 힌트 없음(빈 칸), 개수 표시는 다른 묶음과 같다, 막대 색 `#CFD3D8`.
- done 항목: `.it.done{opacity:.55}`, 왼쪽 위험 점(sev) 색 `#CFD3D8`. 그 밖의 모양·선택(`.on`)·클릭은 같다 (눌러서 다시 볼 수 있다).
- 상품 거르개(`sku`)는 done 묶음에도 똑같이 적용된다.

## 만들 것
1. **상태 상자**: Today 화면(`src/app/(app)/page.tsx`의 `SavingsProvider`와 같은 높이)에 "이 화면에서 끝낸 항목" 상자(클라이언트 context). `markDone(itemId, { simulated: boolean })`. 기존 `SavingsProvider`에 합쳐도 되고 따로 둬도 된다. 서버 전용 코드 import 금지.
2. **켜는 곳 (지금 "+$N just now"를 켜는 두 곳과 같은 순간)**:
   - 답장 칸 Send 성공 (`reply-panel.tsx` `next.ok`): 그 분쟁 항목. `simulated` = 결과가 simulated일 때 true.
   - 추적번호 등록 (`tracking-register.tsx` `countsAsDone(next.kind)`): `tracking` 항목. dry run/simulated면 true.
   - 실패·차단·확인 취소는 켜지 않는다. 답장 칸 [Reset]/다시 쓰기는 끄지 않아도 된다(시안 `replay`는 끈다 — 끄면 더 좋다).
3. **목록**: 왼쪽 목록이 상자를 읽어 위 시안 동작대로 다시 묶는다. 묶기 결과(어느 항목이 어느 묶음인지)는 순수 함수로 두고 단위 테스트한다. 서버가 만든 `TodayView`는 그대로 받는다 (서버 컴포넌트를 클라이언트로 바꿔야 하면 목록 묶음 부분만 클라이언트로 감싼다).
4. **"Simulated" 표시 (정직 규칙)**: done 묶음 안 항목이 **모두** simulated면 제목은 `Done today · Simulated`(ko `오늘 완료 · 시뮬레이션`). 하나라도 실제 전송이면 제목은 `Done today`이고, simulated인 항목 줄에만 작은 `Simulated` 글(기존 `case.progress.simulated` 키 재사용 가능). 문구는 `config/copy.en.json`·`copy.ko.json`에 새 키(`today.group.done`, `today.group.doneSimulated` 등)로.
5. 선택된 항목이 done이어도 오른쪽 상세는 그대로 (지금 보내기 뒤 화면 유지).
