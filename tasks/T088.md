> **가장 중요한 규칙**
> 1. **쓰기(send-message, make-offer, 추적 등록) 뒤에는 지금처럼 바로 지운다** — 녹화 모드에서 보낸 직후 화면은 새 상태. 보내기 직전 검사(`readDetail` 등)는 지금처럼 캐시를 거치지 않는다.
> 2. 데모 모드 관문·기록기·캐시 비밀값 규칙은 T084 그대로. 공개 모드 쓰기 0회.
> 3. 화면 숫자·문구·순서 무변경. 실제 PayPal·AI 호출 금지(가짜로 시험), 개발 서버 금지. `.env` 읽지 않음.

## 만들 것
1. **stale-while-revalidate**: 들어온 지 90초(`READ_CACHE_TTL_MS`) 안이면 지금처럼 그대로. 90초가 지났지만 **최대 10분**(새 상수, 이름·값을 머리 주석에) 안이면 **지난 값을 바로 돌려주고**, 같은 경로의 새로 읽기를 뒤에서 한 번만 시작한다(진행 중이면 다시 시작하지 않음). 새로 읽기가 2xx면 바꿔 넣고, 실패하면 지난 값을 그대로 둔다(10분이 지나면 버림). 10분이 지났으면 지금처럼 기다려서 읽는다.
2. 뒤에서 읽기도 실제 호출이므로 기록기(서랍)에 지금처럼 남는다 — 거짓 줄 없음. 뒤에서 읽기가 끝나기 전에 쓰기로 그 키가 지워졌으면, 늦게 도착한 옛 응답이 지운 키를 다시 채우지 않게 한다 (세대 번호 등).
3. (선택) **서버가 뜰 때 한 번 데우기**: `src/instrumentation.ts`의 `register()`에서 Node 런타임일 때 Today 읽기(GET만)를 한 번 시작하고 기다리지 않는다. 실패는 조용히 무시(로그에 비밀값 없음). 시험 환경·빌드 중에는 돌지 않게. 넣었으면 보고서에 이유와 끄는 방법.
4. 머리 주석·보고서에 "화면에 최대 10분 전 값이 보일 수 있다, 쓰기 뒤에는 바로 새 값"을 적는다.
