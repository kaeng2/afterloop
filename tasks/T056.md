## 배경
지금 화면의 답장 인사말이 "Hello," / "안녕하세요,"이고 지호 서명이 "AfterLoop"으로 나온다. 사람 결정: 인사말·서명에 이름을 넣되 **이름은 AI에 값으로 보내지 않고** 토큰으로 넘기고 코드가 채운다. 서연 = 영어 "Seo-yeon" · 한국어 "서연 님", 서명 = "Hannah, Fernwood Knits".

지금 main의 `npx tsc`가 한 곳에서 실패한다: `src/ai/prompts/reply.ts`의 `DEFAULT_FACT_MEANINGS`에 새 종류가 없다. 이 작업이 고친다.

## 만들 것

### 1. 토큰 종류
- `src/ai/tokens.ts`의 종류 목록에 `BUYER_NAME`·`SELLER_NAME`을 더한다 → `⟦BUYER_NAME_1⟧`·`⟦SELLER_NAME_1⟧`가 올바른 토큰이 된다 (지금 문법 그대로).
- `formatFact`: 이름 종류는 값을 그대로 돌려준다 (언어별 꼴은 값이 이미 그 언어 꼴이다).
- `checkTokens`: 이름 토큰도 다른 토큰처럼 초안·전송본 개수가 다르면 `missing`/`extra`. 이름 값 글자를 "직접 쓴 사실값"으로 세지는 않는다 (이름 검사는 하지 않는다).

### 2. 이름 사실값 만들기 (`src/ai/names.ts`)
```ts
loadReplyNames(): ReplyNames                       // config/rules.json의 reply.names를 작은 zod 스키마로 읽는다. 틀리면 예외
nameFacts(input: { names: ReplyNames; buyerId?: string; locale: FactLocale }): FactToken[]
```
- `⟦SELLER_NAME_1⟧`은 언제나 하나 (값 = `sellerSignature`).
- `⟦BUYER_NAME_1⟧`은 `names.buyers[buyerId][locale]`이 있을 때만. 없으면(표에 없는 구매자, 그 언어 꼴 없음, `buyerId` 없음) 만들지 않는다.
- 같은 분쟁의 영어 초안용은 `locale: 'en'`, 전송본용은 구매자 언어로 부른다. 토큰 이름은 같고 값만 다르다. **영어 꼴은 있는데 전송본 언어 꼴이 없으면 두 쪽 모두 이름 토큰을 만들지 않게** 하는 도우미를 하나 둔다 (예: `nameFactsPair({ names, buyerId, draftLocale: 'en', outgoingLocale })` → `{ draft: FactToken[]; outgoing: FactToken[] }`). 이름이 한쪽에만 있으면 토큰 검사가 막아 버리기 때문이다.

### 3. 프롬프트 — 이름 값이 AI에 가지 않는다
- `ReplyInput`의 `buyerFirstName`·`sellerName` 칸과, 그 값을 `<reply_task>`에 넣던 `buyer_first_name`·`seller_name` 줄을 **없앤다.** 쓰던 곳이 있으면 고친다 (지금 `src/app/`에서는 안 넘긴다 — T009 보고서).
- `<facts>`의 이름 토큰 줄 뜻 (`DEFAULT_FACT_MEANINGS`):
  - `BUYER_NAME`: `the buyer's name, already including the right honorific for the language. Use it in the greeting. Do not add honorifics.`
  - `SELLER_NAME`: `the seller's signature. Use it once to sign off at the end.`
- 시스템 프롬프트 규칙 (초안): `<facts>`에 `⟦BUYER_NAME_1⟧`이 있으면 인사말을 `Hello ⟦BUYER_NAME_1⟧,` 꼴로, 없으면 `Hello,`. `⟦SELLER_NAME_1⟧`은 맨 끝 서명으로 한 번. 이름·가게 이름을 글자로 지어내지 않는다.
- 번역 프롬프트: 이름 토큰을 그대로 두고 **"님"·"様"·"さん"·"Herr/Frau" 같은 호칭을 덧붙이지 않는다** (값에 이미 들어 있다).

### 4. 호칭 겹침
가짜 번역기가 `⟦BUYER_NAME_1⟧ 님`을 돌려주면 채운 뒤 "서연 님 님"이 된다. 이 경우를 **검사 실패로 막는다**: `ReplyTranslation`에 이름 토큰 바로 뒤에 호칭(ko `님`, ja `様`·`さん`·`さま`)이 붙어 있으면 `sendable: false`와 고정 사유 코드(예: `check.honorificAfterName` 또는 기존 실패 사유 꼴에 맞춰). 접어서 고치지 않는다 (판단은 판매자가 다시 번역해서).
