# T030: 주문 스크립트 보호 — 캡처·승인된 주문을 덮어쓰지 않게

| 레인 | paypal |

| 예상 시간 | 1시간 |

> **비밀값 규칙**: 이 worktree 루트에 사람이 입력한 `.env`가 있다. 어떤 방법으로도 열거나 내용·일부를 출력하지 않는다 (잠금으로도 막혀 있다). **이 작업은 실제 PayPal 호출을 한 번도 하지 않는다.** `npm run sandbox:*`를 실행하지 않는다 (지금 있는 주문 12건과 링크를 아침에 사람이 쓴다). 가짜 클라이언트 단위 테스트만 한다.

## 수정 가능 폴더
- `scripts/create-sandbox-orders.ts`, `scripts/capture-sandbox-orders.ts`, `scripts/sandbox/` (필요한 공용 모듈)
- `tests/unit/sandbox-*.test.ts`

이 밖은 수정하지 않는다. 특히 `src/`, `tests/acceptance/`, `seed/`, `config/`, `package.json`, `tests/sandbox/manifest.json`, `reports/sandbox-approve-links.md`.

## 목표
아침에 사람이 결제를 승인하고 캡처하는 동안, 스크립트를 실수로 다시 실행해도 이미 승인·캡처된 주문의 기록이 사라지지 않게 한다.

## 고칠 것
1. **캡처된 주문은 어떤 경로로도 다시 만들지 않는다.** manifest에 `captureId`가 적힌 주문은 상태 조회가 404·403·400이거나 실패해도 그대로 둔다 (지금은 4xx면 새로 만들어 덮고 `captureId`가 사라진다). 경고 한 줄을 출력한다
2. **옵션 없는 `npm run sandbox:orders`**: manifest에 주문 ID가 이미 있는 키는 POST하지 않는다. 12건이 모두 있으면 아무것도 만들지 않고 "already created — use `-- --status` to check, `-- --fresh` to recreate expired ones"를 출력하고 종료 코드 0. 없는 키만 만든다. manifest의 `captureId`·`previousOrderIds`·`disputes`를 지우지 않는다
3. **`--fresh`는 살아 있는 주문을 버리지 않는다.** 주문마다 먼저 상태를 조회해서 `APPROVED`·`COMPLETED`는 그대로 두고, `CREATED`·`PAYER_ACTION_REQUIRED`·만료·404만 새로 만든다. 결과 표에 건별로 "kept (approved)", "kept (captured)", "recreated"를 적는다. 상태 조회가 네트워크·5xx로 실패한 주문은 건드리지 않고 "skipped (status unknown)"으로 적고 종료 코드 1
4. **전부 실패한 `--fresh`가 링크 파일을 덮지 않게.** 새로 만든 주문이 0건이면 `reports/sandbox-approve-links.md`와 manifest를 그대로 둔다. 일부만 성공하면 성공한 건만 바꾸고, 링크 파일에는 12행을 모두 유지한다 (바뀌지 않은 행은 기존 링크 그대로, 승인·캡처된 행은 링크 대신 상태 표시)
5. **`--`를 빼먹은 실행 막기.** `npm run sandbox:orders --fresh`처럼 `--` 없이 주면 npm이 옵션을 삼켜 옵션 없는 경로가 돈다. npm이 그때 넣는 환경 변수(`npm_config_fresh`, `npm_config_status`)를 보고, 있으면 아무것도 호출하지 않고 "옵션은 `--` 뒤에: `npm run sandbox:orders -- --fresh`"를 출력한 뒤 종료 코드 1. 캡처·분쟁 스크립트의 옵션에도 같은 보호가 필요하면 넣는다
6. **캡처 결과 구분** (`capture-sandbox-orders.ts`): 캡처 응답의 `purchase_units[].payments.captures[].status`가 `COMPLETED`일 때만 "captured · ok"로 적고 `captureId`를 기록한다. `PENDING`은 `captureId`는 기록하되 "captured · pending (사유)"로, `DECLINED`·`FAILED`는 "capture failed"로 적고 종료 코드 1. 이미 `captureId`가 있는 주문은 다시 캡처하지 않는다
7. 링크 파일 맨 위 안내에 "이 파일은 마지막 실행이 쓴 것만 쓴다. 승인을 시작한 뒤에는 `--fresh`를 다시 실행하지 않는다"를 추가한다 (다음에 스크립트가 파일을 쓸 때 들어가도록 코드만 고친다. 지금 있는 파일은 건드리지 않는다)

## 완료 기준 (단위 테스트, 가짜 클라이언트만)
- [ ] 위 1~6 각각의 사례: 특히 "`captureId` 있는 주문 + 상태 조회 404 → 그대로", "12건 다 있는 manifest에서 옵션 없는 실행 → POST 0회", "`APPROVED` 3건 + `CREATED` 9건에서 `--fresh` → 9건만 새로, 3건 보존", "`--fresh` 전부 실패 → 파일 불변", "`npm_config_fresh=true`에서 옵션 없는 실행 → 호출 0회·종료 1", "캡처 `PENDING`·`DECLINED`"
