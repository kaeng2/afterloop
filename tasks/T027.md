## 목표
T008 검증에서 나온 보강. "구매자가 받는 메시지의 금액 = API 본문 금액"과 "채워지지 않은 토큰은 구매자에게 가지 않는다"를 실행 층에서 한 번 더 막는다. 계약(`ExecuteInput`, `ExecuteResult`)과 AC11·AC12는 바꾸지 않는다.

## 고칠 것
1. **직접 쓴 금액 거부 범위 넓히기** (필수). 메시지 초안에 자리표시자가 아닌 금액이 직접 적혀 있으면 호출 전에 거부한다. 지금 잡는 두 모양에 더해: `USD 7.20`·`7.20 USD`·`US$7.20`, `7.20 dollars`·`7 dollars`, `7.20달러`·`7달러`, 전각 숫자·전각 기호(`＄７`), 통화 기호 없이 소수 둘째 자리까지 적힌 수(`7.20`), `₩`·`€`·`£`·`¥` 금액. 날짜(`11/12`, `2026-11-12`), 주문·추적번호 같은 긴 숫자열, `3 weeks`·`3주`처럼 금액이 아닌 수는 막지 않는다 (경계는 단위 테스트 표로 남긴다)
2. **남은 토큰 거부** (필수). 자리표시자를 채운 뒤 `{{…}}` 또는 `⟦…⟧`(사실값 토큰, SPEC 3장)이 하나라도 남아 있으면 호출 전에 거부한다. `⟦…⟧`는 이 층에서 채우지 않는다 (채우는 것은 T010). `nextAction`은 "초안을 다시 만들라"는 안내
3. **빈 메시지 거부** (필수). 채운 뒤 메시지가 비었거나 공백뿐이면 `make_offer`·`send_message`·`accept_claim` 모두 호출 전에 거부한다
4. **검증 순서** (필수). 모든 거부 검사(승인, 분쟁 ID, 허용된 수, 확인란, 금액, 메시지)를 끝낸 **뒤에** 중복 승인 기억을 본다. 이미 성공한 `planId`라도 지금 입력이 거부 대상이면 거부를 돌려준다
5. **응답 상태** (필수). `status`가 2xx 정수일 때만 성공으로 처리하고 기억한다. `status`가 없거나 수가 아니면 실패
6. **문구를 영어로** (필수). `error`와 `nextAction`은 판매자 화면(영어, SPEC 1장)에 그대로 나갈 수 있는 영어 문장으로 바꾼다. 문구는 지금처럼 `src/exec/` 한 곳의 상수에 모아 두고, 상수 이름을 안정적인 키로 쓴다 (나중에 ui 레인이 `config/copy.*.json`의 `exec.*` 키로 옮길 수 있게). 엔드포인트·상태 코드 외에 응답 본문·구매자 정보·토큰은 싣지 않는다
7. **단위 테스트 보강** (필수). `offer_type`·`accept_claim_type` = `plan.refundType`, 응답 본문에 토큰처럼 보이는 값이 있어도 `error`·`nextAction`에 실리지 않음, 위 1~5의 경계 사례

## 그대로 둘 것 (컨트롤 타워 결정)
- 중복 승인 기억은 주입된 `call` 참조별로 둔다 (AC12와 맞음). 서로 다른 `call`로 같은 계획을 실행했을 때의 중복은 `PayPal-Request-Id`(같은 값)가 PayPal 쪽에서 막는다. 화면(T009)은 같은 클라이언트의 `call`을 재사용한다
- 지시서에 없던 방어 거부(금액 null·`refundType` null·`disputeId` 불일치 등)는 유지한다
