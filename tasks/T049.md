## 배경
`executeMove`는 같은 `call`로 이미 성공한 계획을 다시 실행하면 호출 없이 이전 결과를 돌려준다 (중복 클릭 방지). 그 기억의 키가 **계획 ID뿐**이다. `send_message` 계획의 ID는 메시지 내용과 무관하게 분쟁마다 하나라서, 같은 `call`로 같은 분쟁에 **다른 메시지**를 보내면 요청 번호는 달라도(T041) 호출이 나가지 않고 `ok: true`가 돌아온다. 화면이 `call`을 재사용하면 두 번째 답장이 "보냈다"고 표시되면서 실제로는 안 나간다.

## 고칠 것
중복 방지 기억의 키를 **요청 번호**(`built.request.requestId` = hash(계획 ID + 엔드포인트 + 보내는 본문))로 바꾼다.
- 같은 계획 + 같은 본문을 다시 실행 → 지금처럼 호출 0회, 이전 성공 결과
- 같은 계획이라도 본문(메시지·금액)이 다르면 → 새 호출 1회
- 실패한 실행은 기억하지 않는다 (지금 동작 유지)
- 거부 검사(승인 없음, 계획 불일치, 허용되지 않은 수 등)는 지금처럼 기억보다 먼저 한다
- 주석·문구에서 "계획 ID 기준"이라고 적힌 곳을 사실에 맞게 고친다

## 완료 기준 (단위 테스트, 가짜 `call`만)
- [ ] 같은 `call`·같은 분쟁에 메시지 A → 메시지 B: 호출 2회, 두 요청 번호가 다르다, 둘 다 `ok: true`
- [ ] 메시지 A를 두 번: 호출 1회, 두 결과가 같다
- [ ] make-offer: 같은 금액·같은 메모 두 번 → 호출 1회. 메모만 다르면 → 호출 2회
- [ ] 첫 실행이 실패(500, 예외)한 뒤 같은 입력으로 다시 → 호출이 다시 나간다
- [ ] 서로 다른 `call` 사이에는 기억이 섞이지 않는다 (지금 동작 유지)
- [ ] 기존 단위 테스트 통과 (기대값을 바꿨으면 바꾼 곳과 이유를 보고서에 적는다)
- [ ] `npm test`, `npx tsc --noEmit`, `npm run lint`, `npm run test:acceptance` (이 작업과 무관한 알려진 실패가 있으면 그것만인지 확인해 보고서에 적는다)
- [ ] 실제 PayPal 호출 0회
