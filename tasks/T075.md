> **가장 중요한 규칙**
> 1. **숫자 일치 조건 (AC33)**: `forecastReply`에서 `text === anchorText`(AI 기본 초안)면 `expectedCostCents` = `recommend(board)`의 fight 평가 기대 손실 (서연 3680¢). 기본 초안이 무엇이든 성립해야 한다 (AI 초안은 열 때마다 다르다). 시안의 숫자(8%, $15, N_FEE 8, N_PRICE 72 등)를 그대로 쓰지 않는다 — 비용은 기존 가정값(`params`: f·t·p_win, 분쟁 금액)에서.
> 2. 확률은 통계가 아니라 가정이다. 가중치는 `config/reply-model.json`에서만 읽는다 (코드에 숫자로 쓰지 않는다). **환불 약속 특징(backup·noRefund)은 없다.**
> 3. 답장 특징 판정은 **코드 규칙**(정규식). AI를 부르지 않는다. 같은 입력이면 같은 결과 (Math.random 금지).
> 4. `tests/acceptance/`는 실행만. AC33이 틀렸다고 판단되면 고치지 말고 근거와 함께 보고.

## 만들 것
1. **`detectReplyFeatures(text)`** (`DetectReplyFeaturesFn`): 시안 `RX`를 옮기되 키는 계약의 `ReplyFeatureKey`(apology·cause·ask·date·lang·blame·vague·refundNow)만. 문장 단위로 찾고 걸린 첫 문장을 `hits`에. `lang` = 구매자 언어 글자(한글 등)가 있거나 번역 대상(영어 초안은 보낼 때 한국어로 번역되므로 화면은 `true`로 넘길 수 있게 — 판단 규칙을 보고서에 적는다). 날짜는 영어 월 이름·"11월 N일"·"11/N" 모두. 정규식은 긴 입력(10만 자)에서도 느려지지 않게 (이차 시간 금지 — 테스트로 잰다).
2. **`forecastReply(input, params?, rules?, model?)`** (`ForecastReplyFn`):
   - 시안 꼴: z = base(intercept + threat·카드사 언급 + unanswered·무응답 + tone·화난 어조) + delayPerDay·delayDays + Σ 특징 가중치 → pChargeback = σ(z). 환불 몫 = (1−pCB)·σ(qz) (시안 `refundSplit`), 기다림 = 나머지. 빈 글 = 특징 없음(답장 안 함).
   - 비용: 기다림 = t, 환불 = 분쟁 금액 + t, 차지백 = 분쟁 금액 + f + t — **params에서** (`timeCostCents`, `feeCents`, `board.amountCents`).
   - **보정 (숫자 일치)**: 기준 초안(`anchorText`)의 예측 기대 비용이 `recommend(board, params, rules)`의 fight 기대 손실과 **정확히 같도록** 보정 항(예: z에 더하는 상수를 닫힌 꼴 또는 이분법으로 찾기 → `parts`에 `calibration`)을 정한다. 그 뒤 입력 글은 같은 보정 위에서 특징 가중치만큼 움직인다. fight가 막혔거나 답장이 불가한 보드면 보정 없이 계산하고 보고서에 적는다. 반올림 규칙(센트 정수)을 정해 `text === anchorText`면 정확히 같은 정수가 나오게.
   - mood·moodBand: 시안 식(`mood` 설정) 그대로.
   - **방법을 보고서와 DECISIONS 요청 칸에 적는다** (사람 결정: "맞추는 방법은 엔진 세션이 정하고 DECISIONS에 적는다" — 컨트롤 타워가 옮겨 적는다).
3. **`riskCurve(events, board, params?, rules?, model?)`** (`RiskCurveFn`): 사건마다 그 시점까지의 정보(무응답 표시·위협·화난 어조·늦은 날 수·추적 없음)로 같은 모델의 pChargeback (답장 특징 없음, 같은 보정). 사건 순서·개수 그대로. 없는 사건을 만들지 않는다.
4. **`weeklySummary(input, params?, rules?)`** (`WeeklySummaryFn`): openDisputes = boards 수, keepableCents = Σ(refund 평가 기대 손실 − best 기대 손실), aiDrafts·usesDemoData는 입력 그대로.
5. 선택지 카드용: 수(fight·offer·refund)별 예상 차지백 %가 필요하다 — `forecastReply`를 수별 대표 글로 부르는 대신, 수별 예측을 돌려주는 작은 함수(예: `forecastMoves(board, signals, delayDays, anchorText)` → `{ move, expectedLossCents(=recommend 그대로), pChargeback }[]`)를 같은 파일에 export한다 (계약 밖 함수 — 화면이 이것을 부른다. 기대 손실은 recommend 값을 바꾸지 않고 옮긴다. refund는 refundNow 특징, offer는 offer 수용 가정에 맞는 값 — 정한 규칙을 보고서에).
