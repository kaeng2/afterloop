### 1. 직접 쓴 금액 거부 범위 (지시서 1)
`message.ts`의 `LITERAL_AMOUNT` 4종. 판정은 **채우기 전 초안**에 한다.

| 모양 | 예 | 문구에 나가는 이름 |
|---|---|---|
| 통화 기호 + 숫자 (`$ ＄ ¢ ₩ ￦ € £ ¥ ￥ ￡`, 사이 공백·줄바꿈 허용) | `$7.20`, `$ 7.20`, `US$7`, `＄７`, `₩9,600`, `€7` | a currency symbol before a number |
| 숫자 + 통화 코드·이름 (`USD KRW EUR GBP JPY`, `달러 센트 dollars cents bucks`, `U.S. dollars`) | `7.20 USD`, `5 usd`, `7달러`, `7 dollars`, `20 cents` | a number followed by a currency name |
| 통화 코드 + 숫자 | `USD 7.20`, `USD7.20` | a currency code before a number |
| 통화 표기 없이 소수 **둘째** 자리까지 | `7.20`, `７．２０` | a number with two decimal places |

전각 숫자(`０-９`)와 전각 소수점(`．`)을 숫자 자리에 넣었다. 막지 않는 것(단위 테스트 "통과" 표 14행): 날짜 `11/12`·`2026-11-12`, 추적번호 `1Z999AA10123456784`·주문번호 `123456789012` 같은 긴 숫자열, `3 weeks`·`3주`·`24시간`, `15%`, `주문 2건`, 소수 첫째 자리 `2.5`, 소수 셋째 자리 `1.205`.

**알고 있는 과차단 1건**: 점으로 쓴 날짜 `11.12`는 거부된다 (소수 둘째 자리 수와 구별할 수 없다). 지시서가 막지 말라고 한 날짜 모양은 `11/12`·`2026-11-12` 둘이고, 거부는 돈이 움직이지 않는 안전한 쪽이라 그대로 뒀다. 단위 테스트 거부 표에 `['점으로 쓴 날짜 (과차단)', ...]`으로 남겼다. 지시서 목록에 없어 **그대로 통과하는 것**: `7,20`(쉼표 소수), `9,600원`, `7불`, `칠 달러` 같은 한글 수사.

### 2~3. 남은 토큰·빈 메시지 (지시서 2·3)
채운 뒤 `{{`·`}}`·`⟦`·`⟧`가 하나라도 있으면 거부하고 `nextAction`은 "초안을 다시 만들라"(`nextRegenerateDraft`)다. `⟦…⟧`는 채우지 않는다 (T010 몫). 짝이 맞지 않는 `{{offerAmount`·`offerAmount}}`도 같은 거부로 걸린다. 채운 뒤 메시지가 비었거나 공백뿐이면 `make_offer`·`send_message`·`accept_claim` 모두 호출 전에 거부한다 (`message.ts`에서 막고, `request.ts`에서 한 번 더 막는다).

### 4~5. 검증 순서·응답 상태 (지시서 4·5)
중복 승인 기억(`WeakMap<PayPalCaller, Map<planId, result>>`)은 승인·분쟁 ID·허용된 수·확인란·금액·메시지·요청 만들기를 모두 통과한 뒤에만 본다. 이미 성공한 `planId`라도 지금 입력이 거부 대상이면 거부가 나가고 호출은 늘지 않는다 (단위 테스트 5건). `status`는 `Number.isInteger(status) && 200 ≤ status < 300`일 때만 성공이고, 그때만 기억한다. `status`가 없거나 문자열·NaN·소수거나 응답이 `null`·`undefined`면 실패이며 기억하지 않는다 (재실행하면 다시 호출). 상태 코드가 없을 때는 코드 대신 `callNoStatus` 문구를 쓴다 (`undefined`·`NaN`이 화면에 나가지 않게).

### 6. 영어 문구 (지시서 6)
`error`·`nextAction`은 모두 `copy.ts`의 영어 문장이다. 단위 테스트가 11가지 거부 경로 + 422·500 + 예외 경로에서 한글(`가-힣` 등)이 없음과 `{{`가 남지 않음을 검사한다. 응답 본문·예외 메시지는 읽지 않는다 (`catch`에 변수를 받지 않는다). T008 검증 "의견 7"(모르는 자리표시자 이름을 error에 되울림)도 같이 막았다: 이제 이름 없이 고정 문구만 나간다.

## 남은 문제
- **금액 판정은 여전히 정규식이다.** `7,20`, `9,600원`, `7불`, 한글 수사(`칠 달러`)는 통과한다. 지시서 1의 목록을 넘는 범위라 넓히지 않았다. SPEC 9-1 "메시지 안 금액 = API 본문 금액"의 마지막 보장은 T010 토큰 검사와 함께 서야 한다 (T008 검증 "컨트롤 타워가 결정할 것" 3).
- **`11.12` 과차단** (위 1절). 구매자에게 "11.12까지"라고 쓴 초안은 거부된다. 데모 문구가 이 모양이면 `11/12`나 `November 12`로 쓰면 통과한다.
- **중복 승인 기억은 그대로 `call` 참조별**이다 (지시서 "그대로 둘 것"). 첫 호출이 끝나기 전의 동시 실행(더블 클릭)은 아직 2회 나간다 (같은 `PayPal-Request-Id`라 PayPal 쪽에서 막힌다). T009 화면이 모듈 수준의 같은 `call`을 넘기고 버튼을 비활성화해야 한다.
- **중복 실행 때 이전 결과의 같은 객체 참조를 돌려준다** (T008 검증 "의견 11"). 지시서에 없어 그대로 뒀다. 받는 쪽이 `sent` 배열을 고치면 기억된 결과도 바뀐다.
- `{offerAmount}`(중괄호 하나)와 `{{{offerAmount}}}`는 여전히 통과한다 (채운 뒤 `{{`·`⟧`가 남지 않는다). 지시서 2는 `{{…}}`·`⟦…⟧`만 요구했다.
- 금액 0·음수·안전 정수 초과(`1e21`)는 여전히 그대로 나간다 (T008 검증 "의견 6"). 지시서 범위 밖이라 손대지 않았다.
- `request.ts`가 `currency_code`에 `plan.currency`를 옮기고 경로의 `disputeId`를 인코딩하지 않는 것도 그대로다 (T008 검증 "의견 9·10", 계약 타입에서는 결과가 같다).

## 컨트롤 타워에 요청할 결정
1. **문구를 `config/copy.*.json`으로 옮기는 작업** — 지금은 `src/exec/copy.ts`에 영어 상수로 있다 (`config/`는 내 수정 가능 폴더 밖). ui 레인 작업으로 낼 때 키는 `exec.<상수 이름>`이고 값의 자리표시자는 `{{endpoint}}`·`{{status}}`·`{{apiMove}}`·`{{allowed}}`·`{{shape}}`다. `src/exec/`가 `config/`를 읽게 바꿀지, 화면이 `error`·`nextAction`을 그대로 쓸지는 그 작업에서 정해야 한다 (T008 검증 "결정할 것" 2).
2. **`11.12` 과차단을 받아들일지** — 소수 둘째 자리 수를 막으라는 지시서 1과 점으로 쓴 날짜를 구별할 수 없다. 거부 쪽으로 뒀다. 날짜를 `11/12`로만 쓰도록 ai 레인 프롬프트(T010 근처)에 못 박는 편이 안전하다고 본다.
3. **지시서 목록 밖 표기(`7,20`, `9,600원`, `7불`)를 여기서 막을지** — `원`·`불`은 한국어 문장에서 오탐이 날 수 있어(`원래`, `주문`은 숫자 뒤가 아니라 걸리지 않지만 `1원`·`2불` 같은 비금액 표기는 드물다) 추측하지 않고 남겼다. 막으라면 `message.ts` 한 줄이다.
4. (확인만) **빈 메시지 거부로 통일했다.** T008은 `make_offer`·`accept_claim`에서 빈 메시지면 `note` 없이 보냈다 (검증 "결정할 것" 6의 허용 항목). 지시서 3이 "세 수 모두 거부"라 거부로 바꿨고, 이제 `note`는 항상 들어간다. 엔진이 `messageRequired: false`인 제안을 메시지 없이 보내려 하면 이 거부에 걸린다 — 그런 경로가 있으면 알려 주면 좋겠다.
