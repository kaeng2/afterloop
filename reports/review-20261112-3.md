## 1. 1단계 (통과/탈락): **통과**

- **주제 적합**
  - PayPal로 해외에 파는 작은 판매자가 구매 후 겪는 분쟁을 다룬다.
  - AI가 하는 일: 번역, 답장 초안과 역번역, 어조 판정, 기록 요약, 상품 설명 고칠 문구.
  - 코드가 하는 일: 원인, 기대 손실, 날짜, 보내도 되는지 판정.
  - PayPal + AI 커머스 주제에 그대로 맞는다.
- **필수 PayPal API 사용**: 공개 데모의 서랍(`S/15-drawer.png`)에 실제 샌드박스 읽기가 200으로 남는다.
  - `GET /v1/customer/disputes` (Read your open cases · 3 cases)
  - `GET /v1/customer/disputes/PP-R-…` (사건 3개)
  - `GET /v2/checkout/orders/{id}` (주문 조회)
- **쓰기 API의 근거**
  - 근거가 있는 쓰기: `send-message`(200), `make-offer`(200), `POST /v2/checkout/orders/{id}/track`(201).
  - 근거는 DECISIONS의 실제 시험 기록과 녹화 모드 코드다.
  - 공개 링크에서는 모두 시뮬레이션이다.
  - 영상의 실제 전송 장면(경희 녹화분)이 화면 증거가 된다.
- **단서**
  - Transaction Search(`/v1/reporting/transactions`)는 /products를 없앤 뒤 **어느 화면도 부르지 않는다** (5장).
  - 그래도 1단계 판정에는 영향이 없다.

## 3. 특별상 5개 + 스폰서상

| 상 | 가능성 | 이유 한 줄 |
|---|---|---|
| Most Creative | 중간 | "타자 칠 때마다 바뀌는 차지백 %"와 "What happens next · Simulated" 흐름은 기억에 남는다. 다만 분야는 실용 도구다. |
| Most Impactful | 중간 | 문제 통계에는 출처가 있다. 하지만 효과 숫자($74→$37, 4.5%→2.1%)는 모두 가정값이고, 실제 판매자 검증은 없다. |
| Best Demo Delivery | 중간 (영상이 kit대로 나오면 높음) | 공개 링크만으로 대시보드 → Desk → Send → 시뮬레이션 → Done today → 상품 점검까지 끊김 없이 돈다. 정직 배지도 촘촘하다. |

| Best Use of Agentic Commerce | 낮음 | 모든 행동을 판매자가 승인하는 설계다. 스스로 움직이는 에이전트가 없다. 설계 의도라 문제 삼지는 않는다. |

  - 오늘 오후 녹화 전에 새 화면을 넣으려면 재배포해야 한다. 녹화 중 재배포 금지 규칙과 부딪치고, 위험이 크다.
