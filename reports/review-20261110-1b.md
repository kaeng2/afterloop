## 1. 처음 본 사람이 이해한 "이 제품은 무엇인가"

> 해외에 파는 작은 가게가 읽지 못하는 외국어 분쟁을 받았을 때, "PayPal 정보만 보면 환불해야 할 것 같은 건이 사실은 답장 한 통으로 풀린다"는 걸 계산으로 보여 주고, 그 답장을 구매자 언어로 PayPal에 실제로 보내 주는 도구.

**1차보다 선명해졌다.** 이유 세 가지:
- 대본에서 말하는 숫자가 가디건 한 쌍($216 → $44)과 서연 한 쌍($74 → $37)으로 줄었다.
- 영상이 서연 전송 성공으로 끝난다.
- 서연 화면에서 "PayPal data only → With carrier data" 비교 카드가 실제로 가장 큰 요소가 됐다 (스크린샷 확인).

남은 흐림: PRD 1장의 소개 문장은 아직 "진단 + 예방 + 합의" 세 가지를 나열한다. Devpost 첫 줄은 위 한 문장처럼 서연 장면 하나로 시작하는 편이 기억에 남는다. 그리고 영상 첫 35초가 Products(시뮬레이션)라서, 첫인상은 "분쟁 예측 대시보드"로 잡힐 수 있다. 0:10 도입 문장("she can't read their messages")이 이걸 잡아 주므로 순서는 그대로 두되, 도입 문장은 빼지 말 것.

## 2. 화면 구조 변경 (5장 → Today 목록·상세 + Products + PayPal activity 서랍)

**판정: 유리하다. 단, 1.5일 안에 다 만들 수 있을 만큼 줄였을 때만.**

유리한 점
- **영상이 끊기지 않는다.** 화면 5장을 오가면 심사위원은 "지금 어디지?"를 매번 다시 잡아야 한다. 목록에서 하나 누르면 오른쪽에 상세가 뜨는 구조는 "할 일을 하나씩 처리하는 하루 아침"이라는 이야기 자체가 된다.
- **서랍은 정직성의 증거 자리가 된다.** "AfterLoop가 대신 부른 PayPal 호출 목록(메서드·경로·200/201)"은 이 프로젝트의 가장 큰 장점(실제 PayPal)을 화면 하나로 보여 준다. 특히 서연 전송 직후에 열면 효과가 가장 크다 (고칠 것 ②).
- 화면 수가 줄어 디자인 일관성을 지키기 쉽다.

불리한 점 (그리고 지금 문서에 남은 어긋남)
- **서연 상세가 더 좁은 자리에 들어간다.** 지금 서연 화면은 1440 폭 전체를 두 칸으로 쓰고도 높이가 약 1,150px이다 (오른쪽 답장 칸이 길다). 왼쪽에 할 일 목록(약 340px)이 붙으면 상세는 더 좁아지고 더 길어진다. 그러면 "비교 카드 + Send 버튼"이 한 화면에 안 들어와 영상에서 스크롤이 생긴다. → 고칠 것 ①
- **AG Grid 자리가 사라졌다.** 1차 리뷰의 "받은 메시지함 표에서 서연 행을 눌러 들어간다"가 AG Grid의 유일한 "일하는 순간"이었는데, 새 구조의 Today는 시안상 카드 목록이다. 그런데 PRD 13장·14장 F7·15장 대본(1:00 "Built on AG Grid (서연 행 클릭)")은 아직 옛 구조를 말한다. → 고칠 것 ④
- **Autopilot이 설 자리가 약해졌다.** FAQ 자동 답변을 뺀 결정(정직성 면에서 옳다) 이후, Autopilot이 실제로 하는 일은 "세 건 모두 사람에게 넘김" 로그 3줄뿐이다. 그런데 대본은 15초를 주고 "Autopilot sorts every case…"라고 말한다. 정렬은 Today 목록이 하는 일이고, 이름이 "Autopilot"인데 자동으로 하는 일이 0개면 질문을 부른다. → 고칠 것 ②
- 새로 만들 것이 셋(목록, Products, 서랍) + 기존 상세 옮기기. 1.5일에 빠듯하다. → 6장 위험 1

## 3. 서연 장면이 영상의 주인공으로 충분히 강한가

**강하다. 이 영상의 이유가 맞다.** "한국어 항의 → PayPal 정보만이면 환불 → 배송사 기록으로 답장 → 한국어로 실제 전송 → PayPal 쪽에도 같은 글"은 기술 구현, PayPal + AI, 임팩트를 한 장면에서 다 보여 준다. 스크린샷 기준으로 비교 카드($74 취소선 → $37)는 깔끔하고 한눈에 읽힌다.

지금 화면에서 주인공을 약하게 만드는 것 (빼거나 줄일 것)
1. **오른쪽 답장 칸이 글자 벽이다.** 코칭 5줄 + 영어 초안 9줄 + 한국어 9줄 + 검사 7줄이 위아래로 쌓여 있다. 영상에서 심사위원은 이걸 읽지 못하고, Send 버튼이 화면 아래로 밀린다.
2. **검사 줄 7개 중 4개는 내부 사정이다.** "No dates or amounts typed in directly", "No extra title next to the buyer's name", "Buyer name 서연 님", "Your signature …"는 심사위원에게 의미가 없다. PRD 8장이 정한 3줄(Facts match · No new promises · Follow-up date 11월 17일)이면 충분하다.
3. **한국어 원문이 기본으로 안 보인다.** 대화 카드가 영어로 먼저 나오고 "Show original"을 눌러야 한국어가 보인다. 대본 첫 박자 "Seo-yeon writes in Korean"과 화면이 어긋난다. "읽지 못하는 한국어"가 화면에 먼저 보여야 번역의 가치가 산다 (시안·PRD 8장 4번은 한국어 원문 + 아래 영어).
4. **원인 칸이 비교 카드를 반복하고, 말이 어렵다.** "PayPal data only: A1 Not shipped → With carrier data: A2 Customs delay"는 바로 위 비교 카드와 같은 "→" 구조를 한 번 더 보여 준다. 게다가 "Not shipped"는 "판매자가 안 보냈다"로 읽혀 Hannah가 잘못한 것처럼 보이고, A1·A2 코드는 처음 보는 사람에게 소음이다. PRD 8장 3번의 한 줄("It's not lost — it's held at Korean customs, waiting for one number." + Code decides)이 화면에 없다.
5. **$72와 $74가 같은 화면에 있다.** 머리글 "Dispute amount $72.00" 바로 아래에 "Full refund $74"가 크게 있다. 눈 밝은 심사위원은 "$72짜리를 왜 $74 환불?"에서 멈춘다 (대응 시간 $2 포함).

말로 줄일 것: 위험 점수 6 → 3은 배지로만 (1차 반영됨, 유지). 코칭은 "with the date checked" 반 문장 (대본 반영됨, 유지).

## 4. 정직성: 실제 / AI / 시연용 / 가정값의 경계

**화면 배지는 잘 되어 있다.** 스크린샷에서 Demo data(배송사 카드, 11/02 문의, 비교 카드의 오른쪽), Assumption(Expected loss), AI suggests(번역·초안·코칭), Code decides(원인·검사)가 정확한 자리에 붙어 있고, 로고 옆 "PayPal sandbox only"도 좋다. 1차 리뷰 ②(대본이 "AI가 통관 보류를 찾았다"고 말하던 문제)는 v3 대본에서 "the code switches to a reply"로 고쳐졌다.

**남은 문제: 영상에서는 배지가 안 읽힌다.** 배지는 작고 회색이다(디자인 기준대로라 맞다). 3분 영상에서 심사위원은 배지를 못 보고 내레이션만 듣는다. 그런데 대본 1:15~2:30은 "The carrier record shows a customs hold"라고만 말하고, 그게 시연용이라는 말이 없다. 나중에 Devpost 정직성 표에서 "배송사 기록 = Demo data"를 보면, **이 장면의 핵심 근거($74 → $37을 바꾼 정보)가 가짜였다**는 인상이 뒤늦게 온다. 먼저 말하면 약점이 아니고, 나중에 알게 되면 약점이다.

"배송사 기록은 시연용"이 약점으로 보이지 않게 하는 방법 (새 기능 없이 말과 자막으로)
- 주장을 "우리가 통관 보류를 찾아냈다"가 아니라 **"PayPal 정보만으로는 틀린 답(환불)이 나온다. 배송사 기록 한 줄이 들어오면 답이 바뀐다"**로 세운다. 이 주장은 배송사 데이터가 시연용이어도 참이다. 실제 배송사 연동은 이미 로드맵에 있다.
- 내레이션에 세 단어만 넣는다: "The carrier record — demo data here — shows a customs hold…". 또는 그 순간 화면 아래 자막 "Carrier record: demo data · Dispute, message, send: real PayPal sandbox".
- 전송 버튼 위 "Simulated send" 글자: 녹화 때는 실제 전송 상태로 바뀌어 있어야 한다. 영상에 "Simulated send"가 찍힌 채 "Sent · 200"이 뜨면 정반대의 오해를 부른다 (지금 스크린샷은 스위치가 꺼진 상태라 정상).

Devpost 정직성 표(PRD 16-1)는 내용이 정확하다. 다만 6줄은 길다. Devpost 본문에는 "실제 PayPal / 실제 AI / 시연용 데이터 / 가정값" 4줄로 줄이고, 정책값·공개 근거는 README에만.

## 6. 남은 1.5일에 가장 위험한 것 3가지

### 위험 1. 만들 화면이 영상 시간보다 많다
- 새로 만들 것: Today 목록, Products(표·큰 숫자·막대·점 그림·처방 카드 4개·AI 색상 문구), 서랍, Autopilot 토글·로그, 서연 상세를 오른쪽 칸에 다시 맞추기. 게다가 PRD 안에서도 Products 구성이 엇갈린다 (8장: 큰 숫자 + 전후 막대 + 점 그림 / 9-3장: 점 그림 + **폭포 차트** + 카드).
- 대비: 영상 초 수 순서로 만든다 — ① Today 목록(5줄, 고정 순서) + 서연 상세 오른쪽 칸 ② Products 가운데(큰 숫자 + 점 그림) + 처방 카드 4개 ③ 서랍(호출 목록만) ④ AG Grid 상품 표. **폭포 차트는 만들지 않는다.** Mike 상세는 목록 한 줄과 상태 문장만. 지호 상세는 지금 그대로 두고 더 다듬지 않는다 (대본에 지호 장면이 없다). 11/11 저녁에 안 된 것은 영상에서 뺀다.

### 위험 2. 단 한 번의 실제 전송 + 매번 다른 AI 초안
- 서연 답장은 녹화 때 한 번만 보낸다. 초안은 열 때마다 바뀌고(서명·낱말이 흔들린 기록이 DECISIONS v2.7에 있다), 한국어는 사람이 검수해야 한다. 녹화 순간에 새 초안이 나오면 검수를 못 한 글이 나갈 수 있다.
- 대비: 녹화 직전에 화면을 열어 그 초안을 팀이 한국어로 검수 → 그 상태 그대로 녹화 시작 → 누름. 초안이 검사에 걸리면 녹화 전에 다시 연다. "Simulated send" 표시가 실제 상태로 바뀌었는지 녹화 전에 확인. 가짜 응답으로 같은 동선을 최소 3번 연습하고, 실패 화면도 미리 본다. 백업 녹화를 남긴다.

### 위험 3. 대본·문서가 새 구조와 어긋난 채 녹화된다
- 대본 1:00 "Built on AG Grid (서연 행 클릭)"은 없어질 화면을 가리킨다. "Autopilot sorts every case"는 Autopilot이 하지 않는 일이다. PRD 13장·F7은 받은 메시지함 AG Grid를 말한다. 화면이 늦게 나오면 대본을 고칠 시간이 없다.
- 대비: 화면을 기다리지 말고 지금 대본을 새 구조로 고정한다 (고칠 것 ②·④ 반영). 녹화 전 체크에 "영상에 찍히는 숫자 = 대본 숫자" 대조 한 줄을 더한다 (추적 2건, $216/$44, $74/$37, 11월 N일). 연습용 분쟁(O04)이 목록·서랍 어디에도 안 보이는지 확인.

## 7. 고칠 것 5개 (효과 큰 순서)

### ① 서연 상세를 "한 프레임에 비교 카드와 Send 버튼"이 들어오게 줄이기
- **문제**: 오른쪽 답장 칸이 코칭 5줄 + 영어 9줄 + 한국어 9줄 + 검사 7줄로 길고, 새 구조에서는 더 좁은 자리에 들어간다. 한국어 원문은 기본으로 숨어 있고, 원인 칸은 비교 카드를 반복하며 "A1 Not shipped"라는 오해할 말을 쓴다.
- **왜 점수를 깎나**: 주인공 장면에서 스크롤이 생기고 글자 벽이 보이면 "방금 뭘 본 거지?"가 된다. 디자인·발표·Best Demo Delivery가 함께 깎인다.
- **고치는 방법** (전부 빼기·접기):
  - "How to reply" 코칭 5줄은 접어 둔다 (한 줄 "5 coaching tips ▸").
  - 검사 줄은 PRD 8장의 3줄만 보인다 (Facts match · No new promises · Follow-up date 11월 17일). 나머지 4줄은 접기 안으로.
  - 영어 초안과 한국어 전송본 중 **한국어를 먼저 크게**, 영어는 접거나 작게 (또는 PRD 8장대로 좌우 두 칸).
  - 대화 카드는 **한국어 원문이 기본**, 영어는 아래 작게 (시안 방식). "카드사에 이의제기"에 강조.
  - 원인 칸의 "A1 Not shipped → A2 Customs delay"는 PRD의 한 줄 "It's not lost — it's held at Korean customs, waiting for one number." + Code decides로 바꾸고 코드(A1/A2)는 작게 또는 숨김.
  - 녹화 해상도를 지금 정하고(예: 1920×1080, 확대 100%), 그 크기에서 비교 카드와 Send 버튼이 함께 보이는지 확인.
- **소요**: 2~3시간 (오른쪽 칸 옮기는 작업과 함께 하면 추가 1시간 정도)
- **분류**: 화면

### ② Autopilot 장면을 영상에서 빼고, 서랍을 "서연 전송의 증거"로 쓰기
- **문제**: FAQ 자동 답변을 뺀 뒤 Autopilot이 자동으로 하는 일은 0개다. 그런데 대본은 15초를 주고 "Autopilot sorts every case by what the code decided"라고 말한다.
- **왜 점수를 깎나**: 이름("Autopilot")과 실제(전부 사람에게 넘김)의 차이는 질문을 받으면 감점이다. 약한 장면이 주인공 바로 앞에 있다.
- **고치는 방법**: 1:00~1:15 Autopilot 장면을 지운다. 대신 서연 전송 직후 PayPal activity 서랍을 2~3초 연다 — 맨 위에 "Send message · POST …/send-message · 200", 그 아래 앞 장면의 "Add tracking · 201", "Read sales by product · 200 · cached", "Read your open cases · 200"이 쌓여 있으면 "이 영상의 모든 행동이 실제 PayPal 호출"이 한 컷에 증명된다. 내레이션 예: "Every step you just saw was a real PayPal sandbox call." 아낀 10초는 서연 장면 또는 여유로. Autopilot 토글·판정 로그는 시간이 남을 때만 만들고, 영상에서는 말하지 않는다. (FAQ 자동 답변을 뺀 결정 자체는 옳다. 그 결정의 결과로 이 장면도 줄여야 한다.)
- **소요**: 대본 30분. 화면은 오히려 줄어든다 (Autopilot 토글·모달을 안 만들어도 됨).
- **분류**: 대본 + 화면(빼기)

### ③ "배송사 기록은 시연용"을 영상에서 먼저 말하고, 주장을 "PayPal 정보만으론 틀린다"로 세우기
- **문제**: 서연 장면의 전환($74 → $37)을 만든 정보가 시연용인데, 영상에서는 작은 회색 배지로만 표시된다. 또 머리글 $72와 비교 카드 $74가 같이 보여 숫자가 안 맞아 보인다.
- **왜 점수를 깎나**: Devpost 표에서 뒤늦게 알게 되면 "핵심이 가짜였다"로 읽혀 기술 구현과 PayPal + AI 평가가 함께 깎인다. 먼저 말하면 정직성 점수가 된다.
- **고치는 방법**:
  - 내레이션: "The carrier record — demo data here — shows a customs hold, so the code switches to a reply." 또는 같은 내용 자막 한 줄.
  - Devpost 첫 문단에 주장 하나: "PayPal data alone says refund. One carrier event changes the answer. (Carrier feed is demo data; dispute, message and send are real PayPal sandbox.)"
  - $74 옆에 작은 글씨 "incl. $2 of your time", 또는 내레이션에서 "a full refund, about $74 with her time" 대신 그냥 "a full refund".
  - 녹화 때 "Simulated send"가 실제 상태 표시로 바뀌었는지 확인.
- **소요**: 대본 20분, Devpost 20분, 화면 문구 10분
- **분류**: 말로 처리 + 대본 (화면 문구 한 줄)

### ④ AG Grid 자리를 하나로 정하고 대본·PRD를 맞추기
- **문제**: 새 구조에는 받은 메시지함 표가 없는데, PRD 13장·F7·대본 1:00은 "받은 메시지함 AG Grid에서 서연 행 클릭"을 말한다.
- **왜 점수를 깎나**: 영상에서 "Built on AG Grid"를 말할 때 화면에 그리드가 없으면 스폰서상은 0이고, 말과 화면이 다르다는 인상만 남는다.
- **고치는 방법**: AG Grid는 **Products의 상품 표 한 곳**으로 정한다. 처방을 켤 때 셀이 깜빡이며 $216 → $44로 바뀌는 순간에 "built on AG Grid"를 한 번 말한다 (0:10~0:45 안). Today 목록은 시안대로 카드 목록으로 두고, 이것을 AG Grid로 바꾸지 않는다 (시간 대비 효과 낮음). PRD 13장·F7 문구를 그에 맞춘다.
- **소요**: 대본 10분, PRD 10분
- **분류**: 대본

### ⑤ Products 가운데를 주인공 하나로: 폭포 차트 빼기, 표는 짧게
- **문제**: PRD 안에서 Products 구성이 다르다 (8장: 큰 숫자 + 전후 막대 + 점 그림 / 9-3장: 점 그림 + 폭포 차트). 시안에는 분포 막대 토글도 있다. 처방 카드 4개 중 하나(customs code)는 "Simulated"다.
- **왜 점수를 깎나**: 35초에 그림 셋이 나오면 숫자 한 쌍도 안 남는다. 1.5일에 만들 양도 늘어난다. "Simulated" 카드를 켜서 $44를 만들면 "실제로 안 되는 처방이 숫자에 들어갔다"는 질문을 받을 수 있다.
- **고치는 방법**: 가운데는 **큰 숫자($216 → $44) + 점 그림(빨간 점 4 → 2)** 두 개만. 폭포 차트·분포 막대는 만들지 않는다 (전후 막대는 시간이 남으면). 처방 카드 4개는 그대로 두되 "Simulated" 배지가 분명히 보이게 하고, 대본은 "four fixes — two run in PayPal" 정도로 한 번만 구분한다. 코트·비니 세트 행에서 멈추지 않는다 (1차 지적, 유지).
- **소요**: 줄이는 작업이라 추가 시간 없음 (오히려 1~2시간 절약). 대본 10분.
- **분류**: 화면(빼기) + 대본

## 참고 (작음, 영상 밖)

- 지호 영어 초안에 "If you accept, please reply to this message and I will send the partial refund promptly"가 있다. PRD 8장은 "PayPal에서 수락하면 바로 환불"로 쓰고 "답장으로 수락"은 쓰지 않기로 했다. 제안 메모로 실제 PayPal에 나가는 글이므로, 지호 제안을 실제로 보낼 거라면 보내기 전에 확인. 지호 검사 줄의 "Follow-up date 11월 17일"은 초안에 날짜가 없는데 표시된다. 지호 비교 카드 "$20"과 버튼 "$7"이 나란히 있어 헷갈릴 수 있다 (영상에 지호 상세가 안 나오면 손대지 않아도 된다).
- 서연 영어 대화의 강조 밑줄이 "dispute with my card"까지만 걸리고 "company"는 빠져 있다.

## 결론
