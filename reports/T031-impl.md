- 적용한 모양: 글로 쓴 한글 수 + `원`(`amountKoWordWon` — `삼만 원이`, `이만 사천 원이`, `만 원과`)과 숫자 + 띄어쓰기 + `원`·`불`(새 모양 `amountKoSpacedParticle` — `24 불이`, `24,000 원과`, `2만 원만`).
- 검증 보고서 문제 1의 **12문장이 모두 다시 막힌다** (`literalFacts`에 금액, `ok: false`, `missing`·`extra`는 비어 있음). 지시서가 더 든 `24,000 원과 …`, `2만 원만`, `만 원과`도 막힌다.
- **검증자가 사본에서 "다시 막힌다"고 적은 정상 문장 `주문 2 불만 사항을 확인했습니다.`는 계속 통과한다.** 새 모양에 "수 부분이 두 글자 이상"(`/^\S{2,}\s/`) 조건을 뒀다 — 한 글자 숫자 + 띄어쓰기 + `불만`·`원만`은 수량·목록 번호(`주문 2 불만 사항`, `사이즈 1 원만하게`)가 금액보다 훨씬 흔하고, 막아야 하는 표기(`24 불이`, `2만 원이`, `만 원이`)는 모두 두 글자 이상이다. 이 덕분에 기존 테스트의 기대값을 고칠 필요가 없었다.
- 보고 문자열에는 조사가 들어간다 (`24 불이`, `2만 원만`). 기준 코드는 조사를 전방탐색으로만 봐서 `24 불`이었다. 막는 판정은 같고 원문이 더 많이 남는 쪽이다.

### A2. 긴 입력에서 끝나지 않던 검사 (검증 보고서 의견, `{{` + 공백 2만 자)
- 원인은 두 곳이었다. ① 실행 자리표시자 `\{\{\s*([^{}]*?)\s*\}\}` — `\s*`·`[^{}]*?`·`\s*`가 같은 공백을 두고 겹쳐서 공백 길이에 대해 역추적이 폭발했다. ② 수로 시작하는 모양(`NUM\s*통화`, `NUM${KO_UNIT}*\s+원`) — 앞 경계가 없어 숫자열의 **자리마다** 다시 역추적했다(5만 자면 5만 번).
- 고친 것: 자리표시자는 `\{\{([^{}]{0,200})\}\}`로 바꾸고 이름 양쪽 공백은 코드에서 `trim`한다(이름 길이 상한 200자). 수로 시작하는 모양 앞에 `NUM_HEAD = (?<![0-9０-９])`를 뒀다(앞자리를 포함한 더 긴 자리에서 이미 보므로 잡는 것은 그대로다). 모양 속 `\s*`·`\s+`는 `\s{0,16}`·`\s{1,16}`으로, `dateKanji`의 `[한자]+`는 `{1,8}`로 상한을 뒀다.
- 겹침 검사(`collector.add`)도 함께 고쳤다. 모양이 수천 번 맞는 글에서 비교가 제곱으로 늘었다 — 자리를 시작 위치 순으로 넣고 이웃 둘만 본다 (이미 넣은 자리끼리는 겹치지 않으므로 결과는 같다). `이만 원이 `를 1만 번 이은 입력이 64ms → 3ms.
- 성능 테스트 6개를 더했다 (각 200ms 상한). 실제 측정값: `{{`+공백 5만 자 0.4ms, `⟦`+글자 5만 자 1.0ms, 숫자 5만 자 2.0ms, 한글(`이만 원이 `×1만) 3.0ms, `$`+공백 5만 자 0.5ms, 보통 문장 5만 자 1.2ms. (쉼표 숫자 5만 자 1.9ms도 따로 재 봤다)

### A3. `100%` 재료 판정을 낱말 단위로 (검증 보고서 문제 2·3)
- 재료 낱말을 **글 전체에서** 찾고 자리만 `100%` 둘레(앞 12자, 뒤 16자)와 견준다. 전에는 글을 먼저 자르고 조각에서 찾아, 자른 자리가 낱말 앞 경계처럼 보였다 — `서울에 계신 고객님께는 100% 도착합니다`의 `울`, `원하시면 … 꼭 100% 환불해 드립니다`의 `면`이 재료로 읽혀 약속을 놓쳤다. 두 문장 모두 이제 `newPromises: ["100%"]`다.
- 한글 재료 낱말은 **앞뒤가 모두 한글이 아닐 때만** 재료다(`울 100%`, `100% 울`, `순면 100%`). `서울`의 `울`, `원하시면`의 `면`, `울이지만`의 `울`은 재료가 아니다.
- 재료 목록에 지시받은 것을 더했다: 한글 `메리노울`·`램스울`·`코튼`, 라틴 `lambswool`·`Schurwolle`·`extra fine merino wool`(`merino`는 이미 있었다). 긴 낱말을 먼저 맞춘다.
- 초안 `It is 100% lambswool.` ↔ 전송본 `램스울 제품입니다. 내일 도착을 보장합니다.` → `newPromises: ["보장"]`, 독일어 꼴 → `["garantier"]`. 지시받은 대로 잡힌다.

### A4. 그대로 둔 것

## 남은 문제
- **`모 100%`·`알파카 100%`·`100% 울소재`는 상품 설명인데 약속으로 잡힌다.** 지시받은 목록(`메리노울`·`램스울`·`코튼`·`lambswool`·`merino`·`Schurwolle`·`extra fine merino wool`)만 더했고, 검증 보고서 문제 2가 든 `모`·`알파카`와 붙여 쓴 `울소재`는 목록 밖이라 그대로다. 목록을 넓히는 것은 아래 결정 사항으로 올린다. 1차와 달라진 것은 없다 (초안이 `It is 100% lambswool.`일 때만 1차가 통과시켰다).
- **재료를 찾는 범위는 여전히 글자 수다** (앞 12자, 뒤 16자). 낱말 경계는 글 전체로 보지만 범위는 그대로이므로, `100% 환불해 드립니다. 캐시미어 제품입니다.`처럼 약속 뒤 16자 안에 재료가 오면 약속을 놓칠 수 있다. 바꾸면 기존 테스트의 `100% cotton blend` 같은 꼴에 영향이 있어 범위는 건드리지 않았다.
- **띄어 쓴 금액 + 조사 뒤에 한글이 이어지면 통과한다**: `24 불이었습니다`, `삼만 원이라고 들었습니다`, `24,000 원이라서`. 지시받은 규칙("조사 바로 뒤가 한글이 아닐 때")대로다. 기준 코드는 막았다. 붙여 쓴 `24,000원이라고`는 막힌다.
- **한 글자 수 + 띄어쓰기 + 조사는 금액으로 보지 않는다**: `2 불이 환불됩니다`, `7 원만`. 위 A1의 두 글자 조건 때문이다. 자리표시자 자리를 바꿔 쓴 경우는 `missing`으로 막힌다.
- 자리표시자 이름이 200자를 넘으면 자리표시자로 세지 않는다. 그 안의 금액 글자가 `literalFacts`로 걸려 막는 쪽으로 틀린다.
- 모양 속 공백 상한(16자) 때문에 `24` + 공백 17자 + `달러`는 금액으로 보지 않는다. 사람이 쓴 글에는 없는 꼴이다.
- 검증 보고서의 의견 4~7(`이 달러`·`이 유로`, 자리표시자 속 부호 모양이 아닌 열, 일부만 보고되는 `사천 원`, `24,00 m$`)은 이번 지시 범위가 아니어서 그대로다.

## 컨트롤 타워에 요청할 결정 (재시도)
- **`100%` 재료 목록을 어디까지 넓힐지** (검증 보고서 문제 2의 남은 항목). 지금 목록 밖인 것: `모`, `알파카`, 붙여 쓴 `울소재`·`면소재`, `recycled polyester`·`superwash merino wool`처럼 재료 낱말이 `100%`에서 16자보다 멀리 있는 꼴. 지시받은 7개만 더했다. 넓히려면 어떤 낱말까지 재료로 볼지 결정이 필요하다 (`모`는 한 글자라 `모 100%`만 잡히고 `부모`·`모두`에는 걸리지 않게 낱말 경계를 쓴다).
- **띄어 쓴 금액 + 조사 뒤에 한글이 이어지는 꼴**(`24 불이었습니다`, `삼만 원이라고`)을 막을지. 지시받은 규칙대로 통과시켰고, 막으려면 `원이`·`불이` 뒤의 한글까지 보는 다른 기준이 필요하다 (`원이름`·`불이익`과 가르기 어렵다).
- 계약(`src/types.ts`)·인수 테스트·SPEC을 바꿔야 할 것은 **없다.** `checkTokens`의 반환 모양과 판정 기준은 그대로다.
