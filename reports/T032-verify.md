### 최악 대기 시간 (계산만)
- 호출 1회의 제한 시간: 20,000ms (`llm.ts:51`, `:204`) — SDK가 `fetch`마다 타이머를 건다 (`client.js:793`).
- SDK 재시도: `maxRetries` 1 (`llm.ts:52`, `:205`). 제한 시간·연결 오류·408·409·429·5xx를 재시도한다 (`client.js:650-675`, `:866-878`). → `create` 한 번이 최대 20초 × 2.
- 분류기 재요청: `MAX_ATTEMPTS = 2` (`classify.ts:55`, `:233`). 제한 시간은 `retryable`이라 한 번 더 부른다. → **20초 × (1 + 1) × 2 = 80초.**
- 여기에 SDK 재시도 사이의 대기가 더해진다: 헤더가 없으면 첫 재시도 전 0.375~0.5초 (`client.js:912-921`) → 약 81초.
- 응답이 429·5xx이고 서버가 `retry-after`(초) 또는 `retry-after-ms`를 보내면 SDK는 그 값만큼 잔다. 이 SDK 판(1.6.0)의 상한은 2^31−1 ms다 (`client.js:881-909`). **이 대기에는 `timeout`이 걸리지 않으므로**, 이 경우의 최악은 `2 × (응답 시간 + retry-after + 응답 시간)`이고 80초보다 길 수 있다. (구현 보고서의 "최악 80초"는 응답이 멈춘 경우의 값이다.)

### 병합 차단

### 병합 후 수정
1. **공백 종류와 가림 순서.** 구분 글자는 반각 공백·`-`·`.` 한 자리만 받는다. 줄바꿈, 탭, 공백 두 칸, NBSP, 전각 공백(U+3000), 전각 하이픈(`－`), 엔 대시, ` - `(공백-하이픈-공백)로 나뉜 부호는 프롬프트에 남는다. 또 `clip()`이 **가린 뒤에** 공백을 한 칸으로 줄이므로(`classify.ts:97`: `oneLine(maskPersonal(text))`), 줄바꿈·탭·겹공백으로 나뉜 부호는 `Cause.evidence`·`causeNote`에 **지시서의 변형 꼴 그대로**(`P 1234 5678 9012`, `P1234 5678 9012`) 남는다 — 그 문자열을 `maskPccc`에 다시 넣으면 가려진다. 요청서 목록의 "줄바꿈으로 나뉜 꼴"과 "전각+공백 혼합(전각 공백일 때)"이 여기에 해당한다. 지시서 목록(공백·`-`·`.`)에는 없는 꼴이라 차단으로 보지 않았다. 병합 차단 1과 같은 정규식이므로 함께 고치는 것이 맞아 보인다.
2. **`LLM_TIMEOUT_MS`의 상한이 없다.** 2,147,483,647을 넘는 값(안전한 정수 범위 안)은 설정 오류가 아니고, Node 타이머가 1ms로 바뀌어 모든 요청이 곧바로 제한 시간에 걸린다 (분류는 늘 기본 유형 + `needsReview`가 된다. 예외는 없다). `LLM_MAX_RETRIES`도 상한이 없다 (1000000 허용).

### 의견
1. 빈 문자열·공백만 있는 `LLM_TIMEOUT_MS`·`LLM_MAX_RETRIES`는 설정 오류가 아니라 기본값이다 (`.env`에 `LLM_TIMEOUT_MS=`만 적은 경우). 지시서 요구("음수, 숫자 아님")는 지킨다.
2. 최악 대기 시간 80초는 응답이 멈춘 경우의 값이고, 429·5xx + `retry-after` 헤더일 때는 SDK가 헤더 값만큼 더 잔다 (위 "최악 대기 시간"). 판단은 하지 않는다.
3. `max_tokens` 1024는 Opus 5.5에서 생각 토큰까지 포함한 상한이다 (T006 검증 의견 2와 같음). 잘리면 `LlmResponseError` → 한 번 더 → 기본 유형으로 조용히 내려간다. 첫 실호출 로그에서 `stop_reason=max_tokens`를 볼 것.
4. 부호 오탐: `P 2026-11-10 1234`처럼 `P` 뒤에 구분 글자로 이어진 숫자가 정확히 12개면 가려진다. 드문 꼴.
5. 전화번호 가림 (권장 항목): 안 가려지는 꼴 — `010.1234.5678`, `+1 (415) 555-1234`, `(02) 123-4567`, `415-555-1234`, 전각 숫자. 오탐 — 0으로 시작하는 9~11자리 숫자열(주문번호 `#0123456789`, 추적번호 `0123456789`·`01234567890`), `+0900 2026`, `+100 2000`, `090-100-1050`, `08-1117-2026`. 구현 보고서의 "10자리 숫자열은 걸리지 않는다"는 0으로 시작하지 않을 때만 맞다. 전각 `＠` 이메일은 안 가려진다. 주소는 가리지 않는다 (지시서대로).
6. `causeNote`·`evidence`를 자를 때 표식이 반쯤 잘릴 수 있다 (`⟦PCC…`, `⟦…`). 원문은 드러나지 않지만 화면에 깨진 표식이 보인다.
7. 404(없는 모델 ID)·422·413도 2회 부른다 (다시 물어도 같은 결과일 오류). 지시서 4의 목록에는 없다.
8. `llm.ts:22`의 머리 주석 "주입하지 않으면 `new Anthropic({ apiKey })`를 만든다"는 이제 `{ apiKey, timeout, maxRetries }`다 (주석만 옛 내용).
9. 로그의 오류 줄은 `error=LlmApiError`뿐이라 종류(`auth`/`timeout`/…)와 상태 코드가 보이지 않는다. 실호출 때 400과 제한 시간을 로그로 구분할 수 없다.

- "추적번호·10자리 숫자열·13자리 이상 숫자열·금액·날짜는 걸리지 않는다" → 0으로 시작하는 10·11자리 숫자열은 `⟦PHONE⟧`으로 가려진다 (의견 5).
- "제한 시간의 최악 대기 시간은 80초다" → 응답이 멈춘 경우에 한해 맞다. SDK 재시도 사이 대기(기본 약 0.5초, `retry-after`가 오면 그 값)는 빠져 있다.
- "이 세션이 읽은 `claude-api` 스킬 번들은 … 표에 `claude-opus-5-5`가 없었다" → 내가 읽은 판(2.1.317, cached 2026-10-06)에는 표와 기본 모델 지침 모두에 있다. 구현 결과(`claude-opus-5-5`)는 문서와 같다.
- 그 밖의 주장(범위 5개 파일, 기존 테스트 기대값 변경 0, 101개·878개, `tsc`·lint 0, 인수 테스트 117, 옵션 이름과 단위, 잘못된 값 5가지의 설정 오류, 오류 종류별 `retryable`, 호출 횟수 표, `causeNote` 80자 / 근거 120자, 로그 가림, 실호출 없음)은 내가 확인한 것과 같다.

## 컨트롤 타워가 결정할 것
1. **병합 차단 1의 처리.** 사실: 부호 뒤에 `공백·하이픈·점 + 숫자`가 오면 기본 꼴까지 남고, T006은 붙여 쓴 기본 꼴을 가렸다. 선택지: (가) 재작업 — 끝 경계를 "바로 붙은 숫자만 거부"로 되돌리고(13자리 이상 붙은 숫자열은 여전히 제외), 공백 종류(줄바꿈·탭·겹공백·전각 공백·전각 하이픈)와 `clip()`의 가림 순서를 함께 정리 (나) 지금대로 병합하고 후속 작업으로. (나)를 고르면 그동안 main보다 가림이 좁은 경우가 생긴다.
2. **부호 가림과 13자리 이상 숫자열의 경계를 어떻게 정할지.** `P 1234 5678 9012 3456`(P + 16자리)을 지키려는 경계와 `P 1234 5678 9012 2026-11-10`(부호 + 날짜)을 가리려는 요구는 같은 정규식에서 부딪힌다. 어느 쪽을 우선할지 (개인정보를 넓게 가리는 쪽 / 숫자열을 남기는 쪽) 지시서에 한 줄이 필요하다.
3. **404·409·413·422 등 "그 밖의 4xx"를 다시 물을지.** 사실: 지금은 2회. 지시서 4는 400·401·403만 적었다.
4. **`LLM_TIMEOUT_MS` 상한과 빈 값.** 사실: 2^31−1 초과 값은 1ms 제한 시간이 된다. 빈 값은 기본값이다. 상한(예: 몇 분)을 둘지, 빈 값을 오류로 볼지.
5. **최악 대기 시간.** 사실: 응답 멈춤 80초(+약 1초), `retry-after`가 오면 그 이상. 구현 보고서의 결정 요청 2번(제한 시간 기본값·분류기 재요청 조합)과 함께 볼 것.
6. **전화번호 가림의 오탐.** 사실: 0으로 시작하는 9~11자리 주문번호·추적번호가 `⟦PHONE⟧`이 된다. 권장 항목이라 판정에 넣지 않았다. 구현 보고서의 결정 요청 3번과 같은 사안.
7. `src/ai/tokens.ts`의 부호 정규식은 이번 범위 밖이라 보지 않았다 (구현 보고서 결정 요청 1번).
