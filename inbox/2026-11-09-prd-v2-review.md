# PRD v2 검토 반영 사항 (기준: inbox/2026-11-09-prd-v2.md, Fernwood Knits 버전)

## 적용 규칙
- 원문과 충돌하면 이 파일이 우선한다.
- "기획자 확정 필요" 항목은 임시값으로 진행하고 DECISIONS.md에 미확정으로 표시한다.

## 확정된 결정
1. 원문 구조 유지: 3단 예방 모델, MVP 화면 S1~S5, 대표 시나리오 SC4(서연), 리허설 500회 시뮬레이션.
2. 생성과 판정 분리 (원문 3장 설계 원칙 그대로).
3. 제안률은 판매자 정책값으로 고정 (기본 15%, 한도 20%). 최적화하지 않는다.
4. 날짜·금액·추적번호·통관 상태 등 사실값은 LLM이 쓰지 않고 코드가 토큰으로 채운다. 원문 10-5 토큰 방식을 번역뿐 아니라 모든 AI 초안(코칭 답장, 색상 문구, 통관 안내, 자동 답변)에 적용.
5. 금액은 센트 정수로 계산·비교하고 화면 표시만 반올림.
6. 추적번호 등록은 Orders v2 /track (trackers-batch는 지원 중단, 우리 앱 403).

## 수정 사항

### M1. 10-3 기대 손실 계산식
- 다투기: L_fight = (1 − p_win)(A + f) + t
- 부분 환불 제안: L_offer = p_acc × xA + (1 − p_acc) × (1 − p_win)(A + f) + t
  (거절되면 다투기로 가지만 대응 비용 t는 한 번만 셈. 원문 식은 t를 두 번 셈)
- 전액 환불: L_refund = A + t
- x = 정책 제안률 0.15 고정, p_acc = 0.72(가정)
- 삭제: "x는 판매자 한도(기본 20%) 안에서 5% 단위로 계산하고 $1 미만 차이면 더 작은 제안"
- 삭제: SPEC v1의 p_acc 곡선 값 3개

### M2. 인수 테스트 기대값 (SPEC v1 값 대체)
- AC1 D1 박지호: A=$48, B1, p_win 0.30, p_acc 0.72, f $8, t $2
  → 다투기 4120¢ / 제안 1816¢ / 전액 5000¢, 최소는 제안 → 돈이 움직이므로 오토파일럿 "승인 대기"
- AC2 D3 buyer_m***: A=$35, F1, 배송 완료 기록, p_win 0.80 (원문 9-1의 추적 등록 시 배송 분쟁 승률)
  → 다투기 1060¢ / 전액 3700¢, 제안 대상 아님(색상·사이즈만), 오토파일럿 "건너뜀(악용 의심)"
- AC3: 같은 입력에서 세부 유형만 B1 ↔ F1로 바꾸면 오토파일럿 판정이 승인 대기 ↔ 건너뜀으로 바뀜
- 이전 기대값(Emma·buyer_k 기준, $77.8/$41.8/$57.0)은 모두 폐기

### M3. 추적번호 API
- 8장 S3 등록 후 문구: "✓ 5 trackers added · POST /v2/checkout/orders/{id}/track × 5 · 200" + 행마다 추적번호
- 12장 장면 2: 입력은 GET /v2/checkout/orders/{id}의 추적 정보로 미등록 판정, 실행은 주문별 /track 반복 호출
- 13장 표 7·8번 행을 위와 같이 교체
- 15장 F6 수용 기준: "/track 실제 호출 5건, 건별 결과 표시, 실패 건 행별 오류"

### M4. 서연 건 확대 위험 점수 (10-4)
- 시연 시점(11/10 17:00Z)과 응답 기한(11/12 17:00Z) 사이가 48시간이라 "기한 72시간 이내 +1"이 적용됨
- "두 번째 문의 무응답 +2"와 "24시간 넘게 무응답 +2"는 중복 가산하지 않음 (둘 중 하나만)
- 시작: 카드사 언급 3 + 무응답 2 + 화난 어조 1 + 기한 1 = 7 (High)
- 답장 후: 3 + 0 + 0(어조 판정 보류) + 1 = 4 (Watch)
- 1장 성공 지표, 8장 S5 문구, 10-4 예시, 12장 장면 3의 "6 → 3"을 "7 → 4"로 수정

### M5. F1 판정 기준 통일
- "같은 구매자의 이전 미수령 분쟁 2회 이상(이번이 3번째 이상) + 배송 완료 기록 → F1"
- 5장 F1 판별 신호와 10-1 규칙을 이 문장으로 통일

### M6. E1 예방 조치 통일
- 17-1 기준 적용: 주문 보류를 권하지 않음
- 5장 E1 예방 조치: "발송 전 확인 보류" → "서명 배송, 청구지와 다른 배송지면 판매자에게 확인 알림"

### M7. 시나리오와 우선순위 정합
- F10 오토파일럿 + 로그를 P0(가벼운 버전)으로 올림: 웹훅 없이 [Run autopilot] 버튼 또는 분쟁 목록 조회로 10-6 규칙 판정과 로그 표시. 실제 자동 실행은 자주 묻는 질문 답변만(이메일은 시뮬레이션). 대본 2:20–2:45의 buyer_m 건너뜀 장면을 지키기 위함
- 1장 성공 지표의 실호출 4종: "분쟁 조회, 추적번호 등록, 메시지, 거래 조회(Transaction Search)"로 변경 (환불은 P1)
- 12장 장면 3, 장면 5의 입력 "Webhook" → "웹훅(P1) 또는 분쟁 목록·상세 조회"

### M8. 샌드박스
- 13장 하단 문구에 추가: 앱 설정에서 'Transaction search'도 켜야 함 (반영 최대 10분)
- 한국 개인 계정이 샌드박스 결제에 막히면: US 개인 계정에 한국어 이름·메시지로 생성하고, 국가는 시드로 표시('Demo data')
- 계정 구성: 비즈니스 US 1개(Fernwood Knits) + 개인 5개(서연 KR, 지호 KR, Yuki JP, Lena DE, buyer_m US)

### M9. 개인통관고유부호 처리 원칙 (11장 마지막 문단과 17-1에 추가)

- 통관 안내 문구는 제출 전 관세청 안내로 확인 (원문 17-3 유지)
