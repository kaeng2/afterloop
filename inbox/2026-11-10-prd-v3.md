## 1. 한눈에 보기

AfterLoop는 해외 구매자에게 파는 소규모 판매자를 위한 PayPal 구매 후 코파일럿이에요. 상품별 분쟁 위험을 미리 돌려 보고, 처방을 PayPal API로 실행해 분쟁을 막고, 그래도 터진 분쟁은 구매자 언어로 합의 단계에서 끝내게 돕습니다.

| 항목 | 정의 |
| --- | --- |
| 한 줄 컨셉 | "모두가 AI로 '사게' 만들 때, 우리는 AI로 '다시 사게' 만든다" |
| 해결하는 문제 | 해외 판매 소상공인은 어떤 분쟁이 왜 언제 터질지 모른 채 팔고, 터진 뒤에는 언어·통관·규칙을 몰라 이길 수 있는 분쟁도 진다 |
| 문제 해결 정의 | 분쟁을 사후 처리가 아니라 상품 단위로 진단하고 처방하는 루프로 바꾼다: 진단 → 예방 → 합의 → 리포트 → 다시 진단 |
| 대상 | PayPal로 해외 결제를 받는 1\~5인 온라인 판매자 (데모: 미국 니트 브랜드, 한국·일본·독일 구매자) |
| 핵심 가치 | 덜 잃는다(분쟁 손실), 덜 묶인다(보류 금액), 다시 산다(재구매) |
| 구매자가 얻는 것 | 내 언어로 빠르고 정확한 답, 싸우지 않고 끝나는 해결 |
| PayPal에 주는 가치 | 중소 가맹점의 이탈과 리저브 위험을 줄여 브랜드 체크아웃 재구매를 지킴 |

**서비스 목표 (해커톤 데모 기준)**

1. 상품 진단: 남은 재고로 미래 500개를 시뮬레이션해 예상 분쟁·손실과 처방별 절감액을 범위와 함께 보여준다
2. 분쟁 발생 예방: 추적번호 등록을 PayPal API로 실행하고, 색상 안내 문구를 AI가 쓴다
3. 분쟁 확대 예방: 한국어 구매자의 차지백 위협을 합의 단계에서 막는다 (원인 판단 + 코칭 + 한국어 답장을 실제 PayPal로 전송)
4. 재발 예방: 종결 분쟁의 원인을 다음 달 진단에 되돌린다 (데모에서는 로드맵)

**데모 성공 지표**

- 가디건 예상 손실 **$216 → $44** (시뮬레이션 평균, 범위 표시)
- 실제 샌드박스 API 호출 4종(분쟁 조회, 추적 등록, 메시지, 거래 조회) 성공과 화면의 실제 분쟁 번호·응답 표시
- 서연 건: PayPal 정보만으로는 전액 환불($74) → 배송사 정보를 더하면 답장(예상 손실 $37), 한국어 답장 실제 전송, 확대 위험 6 → 3

## 2. 문제 정의와 근거

분쟁은 거래보다 빨리 늘고, 한 건의 손실은 금액보다 크며, 그 부담은 대응 여력이 없는 중소 판매자에게 더 무겁게 떨어져요. (v2와 같음. 통계 출처는 제출 전 원문 링크 확인)

| 문제 | 근거 |
| --- | --- |
| 분쟁이 거래보다 빨리 늘어남 | 글로벌 온라인 소매 2026년 $6.88조(+7.2%, eMarketer) vs 차지백 2025→2029 +37%(Mastercard·Datos Insights). 미국 소비자 분쟁 2025년 1억 5,800만 건, 2021년 대비 +29% |
| 한 건의 손실이 큼 | 분쟁 1달러당 평균 4달러 이상 손실(Chargebacks911 2026). 판매자가 대응한 카드 차지백 평균 승률 약 20%(Datos Insights × Mastercard 2025) |
| 중소 판매자에게 더 무거움 | 대형 유통사는 가격 인상으로 흡수하지만 소상공인은 못 함(Entrepreneur 2026). 카드 규칙을 잘 아는 소상공인 17.4%, 전담 분쟁팀이 있는 판매자 약 34% |
| PayPal 가맹점 다수가 중소 | PayPal 활성 계정 4억 3,900만(2025 연차보고서), 가맹점 약 3,600만 중 약 75%가 중소기업(업계 추정) |
| 분쟁이 현금을 묶음 | 분쟁 중 거래 대금 보류(PayPal Resolution Center 안내), 소규모 업체 롤링 리저브 10\~15% 사례(영국 금융 옴부즈만 2025) |
| 먼저 대화하면 줄어듦 | 소비자가 판매자에게 먼저 연락하면 차지백 50\~60% 감소 가능(Javelin 2026). PayPal 합의 단계(최대 20일)가 바로 그 기회 |
| 구매 후 경험이 재구매를 정함 | 택배 미도착 시 57.4%가 재구매 안 함(Sendcloud), 나쁜 배송 경험 한 번에 55%가 구매 중단(Bringg) |
| 분쟁 수수료 | PayPal 미국 Standard Dispute Fee $15, High Volume $30. 합의 단계 해결·원만한 합의 시 면제 ([PayPal Merchant Fees](https://www.paypal.com/webapps/mpp/merchant-fees), [FAQ4352](https://paypal.com/us/smarthelp/article/FAQ4352)) |

**왜 한국어 구매자인가:** 해외 판매자가 가장 대응하기 어려운 구매자는 영어를 쓰지 않고 통관 규칙이 다른 국가의 구매자예요. 한국은 개인통관고유부호처럼 판매자가 모르는 통관 요건 때문에 배송이 막히는 일이 있어 '미수령' 분쟁의 원인을 판매자가 스스로 찾기 어려워요. 우리 팀이 한국어를 직접 검수할 수 있어요. (한국 직구 규모·통관 보류 비율 통계는 제출 전 출처 확인 후 추가)

**PayPal의 당면 과제와의 연결:** 2025년 4분기 브랜드 체크아웃 결제액 성장률이 1%로 둔화했고(PYMNTS), 체크아웃 결제액은 재구매 고객이 PayPal 버튼을 다시 누를 때 늘어요. 분쟁 → 보류·리저브 → 현금흐름 위기 → PayPal 이탈 → 체크아웃 감소의 연쇄를 끊는 것이 AfterLoop의 위치예요.

**기존 도구와의 차이:** Chargeflow·Chargebacks911 같은 서비스는 분쟁이 생긴 뒤 싸우는 도구예요. AfterLoop는 남은 재고 기준 상품 진단으로 분쟁 전에 막고, 합의 단계에서 외국어 대응을 코칭하며, 결과를 다시 진단에 되돌립니다.

## 3. 서비스 컨셉: 3단 예방 모델

AfterLoop의 모든 기능은 세 단계 예방 중 하나에 속하고, 상품 진단이 세 단계를 묶는 출발점이에요.

| 단계 | 언제 | 막는 것 | 판매자가 받는 것 | PayPal API | AI의 역할 |
| --- | --- | --- | --- | --- | --- |
| 0. 상품 진단 | 접속 직후, 신상품 등록, 매월 | (모든 단계의 출발점) | "가디건 120장 팔면 분쟁 약 4.5건, 손실 약 $216 (범위 $67\~$360)" + 처방 목록 | Transaction Search, Disputes 조회 | 색상 불만 메시지에서 공통점 찾기 |
| 1. 분쟁 발생 예방 | 판매 준비 · 주문 직후 | 분쟁이 아예 생기는 것 | 추적 미등록 주문 조치, 상품 문구 | Orders /track | 색상 안내 문구 작성 + 역번역 |
| 2. 분쟁 확대 예방 | 합의 단계(최대 20일) | 클레임·차지백으로 커지는 것 | 원인, 확대 위험 점수, 코칭, 구매자 언어 답장 | send-message, make-offer(정책 안에서만, 승인 후) | 번역, 코칭, 답장 초안, 어조 판정 |
| 3. 재발 예방 (로드맵) | 매월 | 같은 분쟁이 다시 오는 것 | 원인 분석, 다음 달 진단 비교 | (웹훅) | 원인 묶음과 요약 |

**설계 원칙**

- **AI는 제안, 코드는 판정:** AI는 번역·코칭·답장 초안·어조 판정·규칙으로 안 갈리는 분류만. 확률·금액·절감액·원인 규칙·위험 점수·실행 여부는 코드가 계산. 화면에 AI suggests / Code decides 배지를 나란히
- **판매자 정책 안에서만 행동:** 돈이 움직이는 행동(환불, 제안)은 항상 판매자 승인 후. AI 답장은 재발송·환불·할인 같은 약속을 정책에 있는 것만 쓸 수 있음
- **사실값은 코드가 채움:** 날짜·금액·추적번호·이름은 AI에 값으로 보내지 않고 ⟦DATE\_1⟧ 같은 토큰으로 넘긴 뒤 코드가 채움
- **숫자에는 출처를 붙임:** Demo data / Assumption / AI suggests / Code decides / cached 배지
- **계산 함수 하나:** 모든 화면의 예상 손실은 엔진 하나에서 나오고, 화면은 계산 결과를 그대로 보여줌 (PRD 숫자를 하드코딩하지 않음)

## 9. 상품 진단과 리허설 (S2)

같은 미래 500개를 '지금 그대로'와 '처방 적용'으로 두 번 돌려 나란히 보여줘요. 가디건은 **$216 → $44**, 약 80% 감소예요.

**9-1. 시뮬레이션**

1. 난수 고정: 상품별 시드로 미래 500개 × 재고 수 × 세부 유형의 난수를 한 번 만듦. 같은 입력이면 항상 같은 결과
2. 주문마다: 세부 유형 순서대로 난수 < 확률이면 분쟁 발생(주문당 최대 1건). 확률 = 기본값 × 처방 배수
3. 분쟁마다: 지금 습관 = 50% 전액 환불 / 50% 다투기, 합의 정책 = 유형별로 기대 손실이 가장 작은 대응(10-3)
4. 같은 난수: 처방 전과 후가 같은 난수를 써서, 차이는 운이 아니라 처방 때문
5. 출력: 평균 손실, 10\~90% 범위(P10\~P90), 평균 분쟁 수, 처방별 폭포

| 처방 | 바뀌는 것 (가정치) |
| --- | --- |
| 추적번호 24시간 내 등록 | A1 확률 ×0.25, 배송 분쟁 승률 0.15 → 0.8 (A2는 0.3 → 0.6) |
| 색상 고지 문구 (AI 생성) | B1 확률 ×0.4 |
| 한국 통관 안내 | A2 확률 ×0.5 |
| 합의 우선 정책 | 분쟁 수는 그대로, 분쟁당 손실 ↓ |

**9-2. 결과**

- 가디건 120장: 지금 그대로 평균 $216 (범위 $67\~$360, 분쟁 약 4.46건) → 처방 4개 적용 평균 $44 (범위 $0\~$104, 분쟁 약 2.07건)
- 점 그림: 빨간 점 4개 → 2개
- 가게 전체: $717 → $253 (센트 합산). 영상에서는 말하지 않고 S1에만 표시

**9-3. 화면 구성**

1. 헤드라인: "Sell as-is: about 4.5 disputes, $216 (likely $67–$360)"
2. **점 그림 (주인공)**: 점 하나 = 주문 하나, 빨간 점 = 분쟁. 왼쪽 4개 → 오른쪽 2개
3. 폭포 차트: 처방별 절감액, 안 켜진 처방은 점선
4. 처방 카드 + 토글: 켜고 끄면 1\~3이 0.5초 안에 다시 계산
5. (v2의 분포 막대는 뺀)

## 10. 핵심 로직

원칙: AI는 제안하고, 코드가 판정한다.

**10-1. 세부 유형 분류**

- 입력: PayPal reason + 구매자 글(한국어 포함) + 배송 이벤트 + 구매자 이력
- 규칙 먼저: UNAUTHORISED → E1 / 같은 구매자 90일 내 INR 반복 + 배송 완료 → F1 / 배송 이벤트에 customs hold → A2 / 추적번호 없음 + INR → A1
- 그 외는 AI가 16개 중 하나 + 확신도 + 근거. 0.7 미만이면 "Check type"
- 실제 시험: 지호 → B1 확신도 0.9 (AI) / 서연 → PayPal 데이터만이면 A1, 배송사 기록을 더하면 A2 (규칙, AI 0회) / Mike → 이전 분쟁 기록(시드)과 배송 완료로 F1 (규칙)

**10-2. 분쟁 발생 확률**

- 주문 하나의 유형별 확률 = 기본값 × 처방 배수 (가디건 기본값 합 3.6%)
- 추적번호 없음은 등록 대비 A1 4배 (S3 문구 "4× more likely"와 같은 값)

**10-3. 기대 손실과 합의 정책**

- 다투기: L\_fight = (1 − p\_win)(A + f) + t
- 부분 환불 제안: L\_offer = p\_acc × xA + (1 − p\_acc)(1 − p\_win)(A + f) + t
- 전액 환불: L\_refund = A + t
- A = 금액, **f = 분쟁 수수료 $15**(PayPal 미국 Standard), t = 대응 시간 비용 $2, **x = 15% 고정**, p\_acc = 0.72 (가정). 제안 금액은 센트로 반올림한 뒤 식에 넣음
- 제안은 색상(B1)·사이즈(B2)만. 악용 의심(F)은 제안 금지
- 합의 정책 = 세 값 중 최소. v2의 "5% 단위 최소값 탐색"은 수락률이 고정이면 항상 5%가 나와서 뺀
- 예: 지호 $48, 승률 0.30 → 다투기 $46.10 / 제안 $19.53 / 환불 $50.00 → 제안 추천. 서연 $72 → PayPal 데이터만이면 환불 $74, 배송사 기록을 더하면 답장(다투기 경로) $36.80
- 참고: 제안이 다투기보다 나은 조건은 x·A < (1 − p\_win)(A + f)로, **수락률과 무관**해요. 지호 건은 승률이 약 89% 미만이면 항상 제안이 유리

**10-4. 확대 위험 점수**

| 신호 | 점수 |
| --- | --- |
| 은행·카드사·chargeback 언급 ("카드사", "이의제기") | +3 |
| 판매자 무응답 (두 신호는 겹쳐 세지 않음) | +2 |
| 화난 어조 (AI 판정) | +1 |
| 응답 기한 72시간 이내 | +1 |

0\~2 Low · 3\~4 Watch · 5 이상 High. 서연: 카드사 +3, 무응답 +2(시드의 11/02 문의 기준), 화난 어조 +1(실제 AI 판정), 기한 0(실제 기한 11/30) = **6 (High)**. 답장하면 무응답이 빠지고 어조는 다음 메시지까지 보류되어 **3 (Watch)**.

**10-5. 번역 검사**

1. 원문 → 영어 (판매자용)
2. 영어 초안 → 구매자 언어 전송본 → 다시 영어로 역번역
3. 날짜·금액·추적번호·이름은 ⟦DATE\_1⟧ 같은 토큰으로만. 코드가 현지 표기로 채움(한국어 11월 17일)
4. **답장 속 날짜의 뜻은 "판매자가 상황을 확인해 다시 연락하는 날"**(답장 후 7일, PayPal 응답 기한보다 늦으면 기한 하루 전). 도착 예상일로 쓰지 않음
5. 토큰 개수·값이 다르면 전송 버튼 비활성화
6. **정책 밖 약속**(재발송·환불·할인 등)이 초안이나 전송본에 생기면 전송 불가, 판매자 확인
7. 개인통관고유부호는 AI에 보내지 않고 가림. 한국어 전송본은 녹화 전 우리 팀이 직접 검수

**10-6. 오토파일럿 규칙 (코드)**

- 승인 대기: 돈이 움직이는 행동(환불, make-offer), 위험 높은 건
- 건너뜀: 악용 의심(F), 카드사 분쟁(EXTERNAL), 확신도 0.7 미만
- 자동 실행: 이번 범위에는 없음 (FAQ 자동 답변은 로드맵)
- 모든 판단은 로그에 규칙 이름과 함께. 제안할 분쟁은 제안을 먼저 보냄 (메시지를 먼저 보내면 PayPal이 제안 링크를 닫음)

**10-7. 재발 예방 (로드맵)**

종결 분쟁을 세부 유형 × 상품 × 국가로 묶어 손실 순으로 정렬하고, 처방으로 연결. 판매자 본인의 분쟁 이력(Transaction Search·Disputes API)으로 승률·발생률을 보정.

## 11. AI가 꼭 필요한 장면

심사위원의 "AI가 빠지면 뭐가 안 되나요?"에 대한 답이에요. 화면에는 AI suggests와 Code decides 배지를 나란히 보여줘요(같은 회색, 테두리 모양과 기호로 구분).

| 장면 | AI가 하는 일 | 없으면 | 코드가 하는 일 |
| --- | --- | --- | --- |
| 서연 답장 (SC4) | 한국어 항의 번역, 상황에 맞는 코칭 5줄, 영어 초안, 자연스러운 한국어 존댓말 전송본, 역번역 | Hannah는 한국어도, 한국 통관도 모름. 번역기 복붙은 말투가 어색해 분쟁을 키움 | 원인 규칙(배송 이벤트 → A2), 기대 손실 비교, 위험 점수, 날짜·금액 토큰, 정책 밖 약속 차단 |
| 어조 판정 | "화난 어조" 판정과 근거 구절 | 점수가 5로 나옴 | +1점 반영 |
| 색상 문구 (SC2) | 분쟁 메시지에서 공통 불만("실내에서 회색") 찾기 → 여러 언어 문구 + 역번역 | 판매자가 원인을 모름 | B1 배수 적용, 절감액 계산 |
| 분쟁 분류 | 규칙으로 안 갈리는 글 → 16개 세부 유형 (예: 지호 B1 0.9) | PayPal reason 5개로는 처방이 안 나옴 | 규칙 우선, 확신도 기준 0.7 |

- **서연 원인(통관 보류)은 AI가 아니라 코드가 정해요.** 배송사 기록에 customs hold가 있으면 규칙으로 A2. 대본과 화면도 이렇게 말해요
- 모델은 서버에서만 호출(claude-opus-5-5), 프롬프트에 구매자 개인정보·개인통관고유부호 없음. 실패하면 "AI unavailable — showing rules only"

서연 장면이 영상의 주인공이에요(75초). 영상에서 말하는 숫자는 가디건 한 쌍과 서연 한 쌍뿐이에요. 합계 약 2분 45초.

**16-2. 공정성과 신뢰**

- 구매자에게도 이익: 대표 시나리오는 판매자가 덜 주는 장면이 아니라, 구매자가 자기 언어로 원인을 듣고 물건을 받는 장면
- 지킬 수 없는 약속은 하지 않음: 도착일을 약속하지 않고 "다시 연락할 날"만. 정책 밖 환불·재발송 약속은 차단
- 부분 환불은 제안일 뿐: 수락 여부는 항상 구매자가 정하고, PayPal 구매자 보호 절차는 그대로
- 악용 의심은 판단이 아니라 보류: F1은 거절이 아니라 "자동 처리 제외 + 사람이 확인". 근거(횟수·배송 기록)를 항상 표시
